# V24 单次环境清理与待审批网格无损归档候选

已执行的清理仅为302个源支持Python字节码，释放5,349,376分配字节；207个Git跟踪/源缺失/其他不满足规则的文件保留。三个虚拟环境均没有上次缓存再生。源哈希前后相同，未处理数据、模型、参考、原始证据或其他项目。详情见 `result.json` 与 `removed.json.gz`。

只读候选是已终止的 `eval_results/inspection_mechanism_v1_20260910`：metadata complete，verification passed。464个分支001/004/012.ply均为单链接、无活动写FD的派生网格，原SHA逐项匹配原inventory，gzip6在内存完整压缩再解压逐字节相同；208个多链接文件排除。原始传感、baseline、truth、scene、指标、冻结源码和清单全部不在范围内。

原分配230,240,256字节，按各gzip文件4KiB块估计126,652,416字节，净省103,587,840字节（98.79MiB）；未计新目录及收据的小开销。单个gzip最多500,944字节。`mesh_compression_candidates.json.gz` 保存完整路径、原/压缩SHA、长度、inode、mtime与实测压缩大小；`mesh_compression_review.json` 绑定原状态/核验/清单哈希和压缩器版本。

**没有执行归档或移除任何网格。** 审批后应使用独立新归档目录，逐文件先写压缩文件，fsync，重新解压验证完整原SHA，确认原文件identity/mtime及无活动写FD，才允许处理原文件；每一步保留收据和中断恢复状态。不能只检验数组近似相等，也不能重跑模拟器生成“相似”模型。

建议归档布局为 `新目录/archives/<项目内原相对路径>.gz`。可用的逐文件恢复底层命令是 `gzip -dc ARCHIVE.gz > ORIGINAL.ply.restore.tmp`，但这**不是可直接执行的整批安全恢复工具**：正式工具还必须核对压缩SHA、解压后的原SHA、拒绝覆盖既有路径、原子发布并恢复记录的文件元数据。整批操作应实现明确的 `--verify` 和 `--restore` 接口后再实施本方案，目前没有声称该新工具已经存在。

归档期间旧PLY路径将不可直接读取；旧严格清单/回放/分析前必须恢复所需原路径并通过原SHA，不能把“少文件”默认为通过。保留全部压缩归档再完整恢复时需要额外约219.6MiB文件空间及安全余量，当前空间不足以同时保留这两套文件；应提前规划恢复容量，或单独审查逐文件可逆转换方案。该容量限制不影响逐字节可恢复性，但不能隐瞒给后续使用者。

本候选没有修改任何实验分数，也不是新增性能证据。旧V9.1从原包重建网格的先例提供保护流程参考，本提案改用保留完整原文件字节的gzip副本，避免依赖重新融合的确定性。
