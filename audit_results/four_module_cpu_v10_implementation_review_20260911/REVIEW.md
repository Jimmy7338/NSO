# V10 四接口实现独立审查

审查范围是 CPU 四模块、现有 Components/Runtime 的新接线、传感器契约、观测反馈、候选和执行门禁。只做源代码检查与人工构造的传感器回归；没有创建实验 world，没有读取任何未来实验结果，没有评价方案效果。

## 结论

四个接口都存在实际控制路径：OV-SDF 更新的观测资产进入条件评分；IGCR 的实际相机历史与已支付预算进入下一轮去重、候选与返程约束；STGHP 选项进入局部动作队列；RPN 的最新地图检查决定每个动作是否可以执行。调用这四个接口只证明接线，不能证明开放词汇、学习不确定性、复杂房间拓扑或整轨迹效果。

已发现 7 个具体问题。其中当前格障碍被旧建图器抹除的问题以真实 mapper 执行和纯合成传感器复现，新增 V10 子类修复，未修改旧冻结建图源。其他修复由主代理完成；完整 runtime 状态转换测试由另一独立代理负责。每项最终状态见本报告的 `review.json`。

## 问题与处理

|编号|问题与影响|修复状态|
|---|---|---|
|R1|`total_budget=0` 通过 runtime 检查，先融合并提交场景，之后才被 FeedbackLedger 拒绝，遗留半初始化状态。|主代理增加正整数预算、前缀成本类型检查及初始化失败回滚，已静态确认。|
|R2|真实终止包无碰撞但未回含朝向锚点时，runtime 判失败而 IGCR 仍记录 `failed=False`；已终止 ledger 的 `finish` 不会改写该事件。|`compute_reward` 在提交终止观测时直接计算未返锚点失败，已静态确认。|
|R3|前缀只检查时间与编号，未检查每个动作的实际位姿变化；编号完整的“右转并瞬移”也可融合。|融合前按 forward/left/right 检查完整 `(row,col,heading)` 转移，已静态确认。|
|R4|每轮重置的 candidate ID 不能独立标识执行选项，局部动作及反馈缺少显式全局来源。|选项增加 episode 内唯一 `option_id`、选择调用 ID、地图/反馈版本与区域；执行上下文与模块日志引用这些字段，已静态确认。|
|R5|旧 `SensorMapper.update` 在插入障碍后无条件将传感原点设为 free，可能擦掉本帧当前格近距离命中，造成门禁错误允许动作。|新增 `ObservedRuntimeMapperV10`；保留先前当前格占据、本帧雷达及深度占据，记录原因与次数。Runtime 已改用该子类，4 项回归全通过。|
|R6|融合成功后模块更新若抛错，packet 已记录但 IGCR 可能未提交，直接重送可能被误当完整 duplicate。|主代理新增 post-fusion 失败封闭：显式关闭并分别保留实际动作数与反馈已提交数，禁止继续；已静态确认。|
|R7|在锚点发生当前足迹不安全时，旧 close 只按位置、朝向和碰撞判成功，可能将安全门拒绝记为任务成功。|主代理将 returned_to_anchor 的几何事实与 failed 分开，后者包含当前足迹不安全；真实终止帧的 compute_reward 也同步纳入该条件，已静态确认。|

异常恢复采用明确失败并停止，不复制或回滚 Open3D TSDF；记录不能把已执行动作重新说成免费动作。

## R5 的独立见证

合成输入采用合法 0.2 m 栅格、180 线束、同步居中相机与雷达，未构造三维场景。其余雷达线束均为最大距离，正前方线束命中 0.05 m；该命中落入机器人当前格。输入通过完整 SensorPacket 校验。

修复前旧 mapper 把当前格设为 0，`safe_grid[current]` 为 true，右转被允许。修复后该格保留为 1，左转、右转、前进与返程查询均因 `current_footprint_not_known_safe` 拒绝。

测试还验证仅 RGB-D 的当前格障碍、后续无命中帧不得清除已有占据，以及四朝向普通传感器序列兼容性。普通序列与旧 mapper 的占据、可见性、相机已见图、全部 quality 字段、surface evidence、TSDF 顶点/三角形/法向/颜色逐数组完全相同。新类不会改写过去结果。

执行命令：

```text
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 .venv-3d/bin/python -m unittest tests.virtual3d.test_observed_runtime_mapper_v10 -v
```

结果：4/4 通过；0 个实验 world；0 个未来结果读取。

## 接口、预算与数值检查

- V8 与 V8.1 的 `measured_assets` 和 `aperture_support` 定义一致；所需宽、深、高、类别票、标记支持字段全部存在。当前资产中的 NumPy 数组和标量由 `json_value` 转换，`digest` 禁止非有限 JSON 数字。
- IGCR 使用的 `point/information/residual/n` 与 QualityMapperV2 的记录匹配；可靠性代理为 `I/(I+.25+100*residual)`。旧支持分母固定，缺失旧测量按 0 计，质量变化保留符号。
- 评分显式将去程 `states/cost` 传入 rate 特征，随后乘去程支付成本还原总收益。计划返程状态不进入预期观测去重；每轮候选完整去程加返程成本不得超过实时余额，返程恢复锚点朝向。
- 每步执行前重新读取当前地图，同时检查当前/下一足迹及下一状态在 `remaining_budget-1` 内的返程。被拒绝时没有环境动作或免费帧。
- 缺失类别 M 精确等同 G；N 仅共同项；S/X 分别使用原类别票/交换票。当前 G/O/S/X/M 共享去程与预算候选，但这些静态路径不代替动态消融证明。

## 能力边界

区域连通筛选与候选图可达性在当前实现中等价，因此不能单独据此宣称拓扑增益。语义仍是人工标记先验，quality/奖励是观测代理，门禁没有学习概率或校准方差。当前格冲突修复证明确定性拒绝行为，不能推出真实硬件运动绝对安全。后续仍须完整 CPU 闭环、逐动作独立回放及另行冻结的效果实验。
