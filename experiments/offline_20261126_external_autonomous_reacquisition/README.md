# 扫描场景中的自主地面补测

本实验以 `Jimmy7338/NSO@8917a30fd82c1550c240e3d31748dd8f4332c73d` 为基线。该版本已有人工指定出口和视角的开发案例。本轮在同一个修订区域规划器上配对比较 A（关闭补测）和 B（自动补测），考察在未知扫描场景中能否复现机制，以及动作开销如何影响覆盖和建图。语义配置和区域规划权重沿用基线。

## 方法

B 检查当前车位相邻、现有通行图无法到达的一步边。两侧中心必须已观测为空闲，原完整扫掠检查必须明确报告缺少正向地面观测。缺失采样点须有有限激光回波支持其上方通行空间。边的另一侧须有由已测自由格连接到的未知边界，评估范围为 3 m。该连通估计参与选点，实际路线由现有通行图和安全检查决定。

候选来自实测有向位姿图中的未访问朝向。程序使用当前相机变换和内参，估计在不同地面高度假设下，缺失采样点能否落入相机有效范围并被有效像素采到。候选评分结合预期补到的采样比例、门后潜在未知格、候选可见的未知格以及往返步数。已观测障碍参与遮挡判断。补测路线计入动作预算，并检查返回起点的余量。

执行每一步后融合新观测。只有补测获得新增正向地面证据、原完整扫掠重新通过且测得返程可行时，才安排过边。实际跨边前再次核验原证书和动作检查。每个缺口最多尝试 3 个视角，连续 2 次无新证据时退出当前补测，单轮最多 6 个视角。补测退出后由原区域规划器继续。观测分数是预测量，回放使用实际融合后的传感数据度量新增证据。

## 复现

在具备前述基线、已登记扫描资产和原仿真依赖的实验目录中执行。冻结文件记录了基线源、场景准入、首帧、对应评价掩膜和依赖的 SHA-256。网格和表面真值仅供评价使用。

```bash
python study.py development
python study.py freeze-parameters
python study.py seal
python study.py run
python evaluate.py
python figures/plot_trajectory_case.py
```

预登记开发回合用于核验自动补测、实际跨边和实体拒绝。四个正式起点各跑一次 A 和一次 B，每轮最多 192 个动作。第 96、192 步仅用实际执行到相应步数的记录。早停另列最后共同时点和真实终点。用覆盖率与 5 cm 距离阈值下的全场景表面 F1 的乘积报告联合质量 J。

压缩归档保留逐步动作、传感包校验值、地图检查点和补测事件。重建逐步传感输入需要对应冻结场景资产。扫描原件单独按其发布方条款取得。
