# Controlled facility-category episodes

The declared matrix contains two simulated parent layouts with two furniture placements each. In each placement, G, S, and X start from the same single observed RGB-D/scan packet. The original selector runs the neutral class-prior visibility policy before and after the first qualifying plan. At that plan G, S, and X select from the original legal candidates using the neutral, aligned, or swapped structural prior respectively. The experiment changes no score coefficient, candidate, mapping input, primitive, or return rule.

Verify the frozen actor, scene binding, initial sensor inputs, and inherited B11 dependencies using `science312/bin/python run.py verify`. Audit existing results with `python3 audit_matrix.py --output matrix_audit.json`. The audit checks exact predecision packet chains, score and candidate hashes, selector modes, action totals, return, and every terminal artifact checksum. Independent reconstruction scoring and the study gate live in the study-level `evaluation/` directory.

Each episode is stored in `layouts/<layout>/runs/<arm>/attempt_001/`. The intervention record contains the complete chosen option and ranked candidate score components. Choices, steps, termination and mesh files retain the original execution record. The two diagnostic scripts reconstruct the measured cold-start safe graph or probe already recorded candidate camera poses with the simulator first-hit renderer. They are post-hoc audits, separate from the frozen planner and outcome evaluation. The first-hit output counts unique five-centimeter sample bins per source part. These counts describe visibility rather than reconstructed area.

Execution began with two independent one-thread actors. After the E1 jobs finished, a scheduling-only handoff retained the original logs and admitted up to four concurrent one-thread actors. The original scheduler's receipts remain in `batch_001/`. The first handoff check on the unavailable kernel child-list interface is retained in `batch_002_schedule_only/`. The successful child-PID validation and authoritative final schedule are in `batch_003_schedule_only/`. Adopted workers retain their original simulator PIDs and artifacts. The new scheduler reports their OS exit status as unavailable and records completion from the terminal artifacts. Wall clock times are shared-host measurements across both scheduling levels.
