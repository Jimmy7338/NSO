# CPU 二维闭环平台与几何基线

交付日期：2026-09-10。对应实施计划第 2 周：在没有 GPU、Habitat 和真实模型权重时持续开展可重复的闭环探索实验。

本阶段已实现平台、两条几何基线、日志/观测归档、统计和图表，并实际完成 **24 个回合**。这些是开发验证实验，不是原 NSO 神经网络系统的论文主结果。

## 环境与复现

新环境为 `.venv-cpu`，独立于上一阶段含 PyTorch 的 `.venv`。已验证 Python 3.12.3 + NumPy 1.26.4 + SciPy 1.11.4 + Matplotlib 3.8.4。CPU 平台的导入、运行和绘图均无需 PyTorch、Habitat、OpenCV、CLIP 或网络下载模型。

最小依赖见 `requirements-cpu.txt`；本次 Python 3.12 环境的全部依赖版本见 `requirements-cpu.lock.txt`。原有三维运行入口通过惰性导入保留。

从项目根目录新建同类环境：

```bash
python3 -m venv .venv-cpu
.venv-cpu/bin/python -m pip install -r requirements-cpu.lock.txt
.venv-cpu/bin/python -m pip check
```

运行二维检查：

```bash
.venv-cpu/bin/python -m unittest discover -s tests/cpu -p 'test_grid*.py' -v
```

运行短回合检查或正式的开发小试，输出目录必须尚不存在：

```bash
.venv-cpu/bin/python scripts/eval_cpu.py \
  --config configs/cpu/smoke.json --output eval_results/my_cpu_smoke

.venv-cpu/bin/python scripts/eval_cpu.py \
  --config configs/cpu/pilot.json --output eval_results/my_cpu_pilot

.venv-cpu/bin/python scripts/eval_cpu.py \

```

从原始回合记录重建汇总与图表：

```bash
.venv-cpu/bin/python scripts/analyze_cpu_results.py eval_results/my_cpu_pilot
```

分析命令重新生成派生的 `summary.json` 和图片；不会改动原始 episode、逐步记录和观测归档。评估命令拒绝复用已有运行目录，防止不同实验混写。

## 平台约定

| 项目 | 当前实现 |
|---|---|
| 场景 | 单房间、多房间、曲折走廊、死胡同、环路、大厅；地图种子控制几何变化 |
| 观测 | 90° 视野、1.5 m 距离的离散射线；障碍表面可见，墙后和角缝遮挡；未知格点为 -1 |
| 栅格 | 默认 0.1 m/格；小试 64×64，规模检查 128×128 |
| 机器人 | 半径 0.1 m；使用带栅格方块余量的保守圆形足迹膨胀 |
| 动作 | 前进一个格点、左转 90°、右转 90°、停止；转向和停止同样消耗动作预算 |
| 位姿 | 完美格点位姿和方向，无估计误差；不报告 SLAM 漂移 |
| 执行碰撞 | 模拟器按完整真实障碍与机器人足迹判定；碰撞不产生位移 |
| 策略输入 | 只包含已观测地图、当前可见掩码、位姿、步数、上一步碰撞反馈 |
| 评价真值 | 独立接口提供完整地图及起点连通可行进掩码；不传给策略 |
| 回合终止 | 动作预算耗尽，或没有可行前沿且转向扫描不再增加观测后主动停止；不以 GT 覆盖率作为停止条件 |

地图边界尺寸和起始坐标已知，内部布局未知。策略得到的是只读副本，修改副本不会改变模拟器真值。射线为有限采样的栅格传感器，不是 RGB-D 摄像机或连续光学模型。

## 两条基线

**nearest_frontier：最近前沿。** 从已观测自由空间中找到与未知相邻、在已知地图中可达的前沿。选最短格点距离的目标；可原地转向获取未知观测时，把当前位置作为零距离候选。同距离以潜在可见未知格点数打破平局。

**gain_per_cost：预计信息增益／代价。** 使用相同前沿、局部执行器和观测；用 `预计可见未知格点数 / (路径格点数 + 估计转向数 + 1)` 选择候选。

二者共同采用四邻域、单位边权的 BFS 最短路径。这里选择 BFS 是因为每条前进边代价相同，此时它给出精确的格点最短路径；当前没有调用 Habitat 的 FMM，也没有宣称复现其局部神经策略。

为控制计算量，每个连通前沿取最多 4 个代表点，最多评估 24 个候选。预计增益使用已知障碍做遮挡，假设未知区域可透视，因此是乐观的几何启发式，不是实际观测收益、严格互信息或训练奖励。

规划仅允许目标中心及路径中心落在已知自由格点；机器人膨胀考虑已知障碍，未知足迹部分仍采用乐观假设。真实碰撞由模拟器约束，碰撞目标会记录到策略的不可通行缓存。两条基线使用同一规则，未向策略提供真实膨胀图。

## 指标与数据

覆盖分母是**起点所属连通分量中的可行进机器人中心格点数**，在真实障碍经足迹膨胀后计算；封闭且不可达的房间不计入分母。分子是已经观测到的该类格点数。面积为分子乘分辨率平方。

这是 `start_connected_robot_center_grid` 口径，与旧 Habitat 的 `aligned_gt_explorable_map` 不同，不可直接把两者的绝对覆盖率拼到一张排行榜。

- 覆盖率、面积、实际路径长度每动作记录一次，包含 reset 后的第 0 步观测。
- 重复访问只统计成功移动后进入已访问位置；原地转向与碰撞不算重复移动。
- 归一化覆盖 AUC 使用统一的最大动作预算。提前停止后保持终止覆盖值到预算终点，不因回合变短而获得统计优势。
- 80%/90% 到达步数未达到时为 `null`，汇总保留未达到数量。
- 多起点先在每张地图内部平均，再计算跨地图均值/标准差。图中的阴影是标准差，不是显著性或置信区间。
- 耗时为实验循环墙钟时间；包含策略、环境、指标和内存记录，不含随后压缩存储与绘图。当前没有固定 CPU 频率，时间仅用于预算估计，不作为严格性能排名。

每次运行产物：

```text
run_metadata.json        # 配置摘要、工作代码摘要、环境、完成/失败状态
config.json              # 本次实际完整配置
requirements.lock.txt    # 本次运行环境依赖快照
summary.json             # 跨地图统计与配对差值
coverage_curves.png       # 覆盖-动作曲线
trajectories.png          # 两种方法的轨迹对照，真值只用于事后显示
episodes.jsonl           # 完成和失败回合清单
<episode_key>/
  episode.json           # 回合汇总、起点、种子、地图摘要、耗时
  steps.csv              # 动作、位置、目标、分项评分、覆盖、碰撞等
  observations.npz       # 每步可见掩码（按 bit 压缩）、位姿、最终已知地图
                         # 另含评价用 occupancy/reachable，不属于策略输入
```

`observations.npz` 配合地图可以逐帧重建已知栅格图，但它不是 RGB-D 缓存；不能被解释为原三维视觉系统的离线训练数据。

## 本次实测

### 10 张开发地图小试

[完整汇总](../eval_results/cpu_pilot_20260910/summary.json)、[覆盖曲线](../eval_results/cpu_pilot_20260910/coverage_curves.png)、[轨迹图](../eval_results/cpu_pilot_20260910/trajectories.png)。

6 种布局共 10 张 64×64 地图，每图一个固定起点种子 101，两条基线共 20 回合，预算 500 动作。

| 指标（跨地图平均） | 最近前沿 | 增益／代价 |
|---|---:|---:|
| 最终覆盖率 | 100% | 100% |
| 归一化覆盖 AUC | 0.8605 | 0.8676 |
| 路径长度 | 22.82 m | 24.40 m |
| 重复移动比例 | 7.18% | 15.78% |
| 每回合实验循环耗时 | 0.706 s | 0.539 s |

所有回合均无碰撞；两种方法均达到覆盖饱和。增益基线的 AUC 在部分地图上反而更差，且平均回溯更多，不能据此宣称全面优越。实验循环阶段进程峰值 RSS 约 93.7 MiB，不包含最终绘图阶段。

已用 20 个回合的打包可见掩码及评价地图独立复算覆盖率，与回合汇总一致。

### 较大地图预算检查

小试发现覆盖饱和后，另设 128×128 的多房间和大厅地图各一张，种子 17，仍为相同起点种子与 500 动作预算。[汇总](../eval_results/cpu_scale_probe_20260910/summary.json)、[轨迹对照](../eval_results/cpu_scale_probe_20260910/trajectories.png)。

| 地图 | 最近前沿覆盖率 | 增益／代价覆盖率 |
|---|---:|---:|
| 多房间 | 39.8% | 72.4% |
| 大厅 | 62.8% | 70.6% |

4 个回合均完成，每回合约 2.7–3.0 秒，实验循环阶段进程峰值 RSS 约 94.4 MiB。该检查表明扩大地图后预算约束能产生可观察差异；**只有两张开发地图，不能当作泛化或统计显著性结论。** 地图调整过程已写入配置用途，后续正式测试需另设未用于调试的地图种子与布局。
