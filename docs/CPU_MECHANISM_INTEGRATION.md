# CPU 语义、结构与可达性机制接通

更新：2026-09-10。对应六周计划第 3 周。此阶段完成可执行机制、普通点估计网络的 CPU 离线训练及开发消融；不等同于最终论文测试，也不声称已经复现旧三维系统的 OV-SDF、STGHP 或 RPN-UQ。

## 实现与可观测接口

- `env/grid_semantics.py`：固定种子的 12 个平滑热点形成 [0,1] 合成显著性场，与场景语义类别、真实图像或开放词汇识别无关。环境每步只返回当前视野内值，视野外为 NaN。策略仅保存已观测值；未观察区域的内部密度为 0。所有方法共享同一场景、语义场、起点和传感器。
- `nso/grid_topology.py`：在已知自由空间中查找两端均为已观测障碍、宽度不超过 7 格的窄通道。先切除，再提取至少 12 格的区域核心，经自由空间扩展恢复通道归属，区域接触形成边。新旧节点按重叠面积一对一匹配；拆分时最大重叠区域继承旧 ID，其他分配新 ID。未知边界不冒充门墙。完整已知四房间样例得到 4 节点、4 条边；部分观测阶段允许区域增减，不能把节点数直接解释为真实房间数。
- `nso/grid_mechanisms.py`：沿用原几何候选生成、已观测自由空间 BFS、足迹约束和碰撞回退；图为空或候选被屏蔽后使用有限扫描及 STOP。目标从可达前沿选择，避免以房间质心作为可行目标。语义项使用候选周围 11×11 范围内已观测显著性的最大值；结构项使用区域前沿数量相对最大值，除以从当前位置到目标区域的图跳数加 1。每 10 步更新区域图。

评分为 `gain_per_cost × (1 + semantic_weight × semantic + structure_weight × structure) × reach_probability`，权重均为 1；关闭模块的项为 0，未使用网络时概率为 1。只有未知可见增益大于 0 的候选参与；分数是启发式，不是实测互信息。该实现是图辅助前沿评分，并非已完成原论文的全套分层规划器。

每次选目标的全部候选、分项、连通状态、预计动作数、是否选中保存在 `candidates.jsonl`；语义、拓扑、RPN 调用及目标切换计数进入 `episode.json`。每回合记录独立的区域图与最终语义记忆。

## 可达性任务与标签

所有候选先经过已知地图上的几何连通约束，`geometric_connected=true` 仅说明当前观测下存在规划路径。它不是未知地图的全局真值。

控制器任务定义为：从选目标时的姿态出发，在 32 个原子动作内到达目标格点和目标朝向，转向计入预算。实际到达标 1，碰撞或用完目标预算标 0。因新观测使原路径失效、回合预算用完导致目标未完成，均作为删失数据标 null；从未执行的候选也为 null。目标超时后在本回合屏蔽该格点。删失样本比例较高，因此网络指标只代表有确定结果的目标，不能外推到全部候选。

消融中的 `gain_control` 与所有机制方法采用相同的 32 步目标预算与回退；保留原始 `gain_per_cost` 作为额外对照。不能直接将两者差异归因于语义或结构。

`nso/cpu_reachability.py` 为新的候选级普通点估计 RPN：5 个特征 → 16 个 tanh 隐单元 → sigmoid，113 个参数。特征仅包含已知路径距离、含转向的预计动作数、最小已知障碍间距、路径邻近未知区域比例和预测增益。采用 NumPy 在 CPU 上离线训练，120 个固定 epoch，不通过验证集选择最优模型。它不是旧卷积 RPN 的替代权重格式，也没有 MC Dropout/UQ。

推理权重只读，每个评估回合结束校验指纹；实验目录复制冻结权重并记录 SHA-256。评估没有优化器或参数更新。

## 复现

使用上一阶段的 `.venv-cpu`，无需新增依赖、显卡或模型下载。以下输出目录必须尚不存在：

```bash
.venv-cpu/bin/python scripts/eval_cpu.py --config configs/cpu/mechanism_train.json --output eval_results/my_mechanism_train
.venv-cpu/bin/python scripts/train_cpu_rpn.py --source eval_results/my_mechanism_train --output eval_results/my_rpn --validation-seeds 201
```

复制 `configs/cpu/mechanism_ablation.json`，将其中 `rpn_checkpoint` 指向新模型，再运行：

```bash
.venv-cpu/bin/python scripts/eval_cpu.py --config configs/cpu/mechanism_ablation.json --output eval_results/my_mechanism_ablation
.venv-cpu/bin/python scripts/analyze_cpu_mechanisms.py eval_results/my_mechanism_ablation
.venv-cpu/bin/python -m unittest discover -s tests/cpu -p 'test_grid*.py' -v
.venv/bin/python -m unittest discover -s tests/cpu -p test_eval_integrity.py -v
```

第二条示例直接使用仓库已归档模型；复现自己的训练时应传入修改后的配置路径。轻量 `.venv-cpu` 不含 PyTorch，旧三维评估冻结测试需要已有 `.venv`。

## 本次开发数据与结果

训练采集：10 个回合，128×128 格，5 类布局 × 地图种子 200/201，起点种子 101，每回合 500 动作，策略为语义加结构。归档：`eval_results/cpu_mechanism_train_20260910/`。

不能只按种子隔离地图：本次环形布局的两个种子产生完全相同的几何（生成器只有少量几何变体，并非所有种子都相同）。训练脚本将验证集出现的几何哈希整体划入验证侧，得到训练 4 个不同几何、验证 5 个不同几何。环形几何的两个不同语义场均在验证侧。训练有 115 个确定结果（102 成功、13 失败），验证有 148 个确定结果（141 成功、7 失败）。原始删失记录保留，不作为负例。

模型和训练曲线：`eval_results/cpu_rpn_20260910/`。

| 验证方法 | BCE | Brier | ECE | 准确率 |
|---|---:|---:|---:|---:|
| 候选 MLP | 0.04425 | 0.00491 | 0.04110 | 99.32% |
| 训练集成功率常数 | 0.21739 | 0.04938 | 0.06575 | 95.27% |
| 预计动作数 ≤ 32 的规则 | 约 0 | 约 0 | 约 0 | 100% |

BCE 中概率裁剪到 [1e-7,1−1e-7]。ECE 使用 10 个等宽概率箱，仅用于评估。确定性网格中动作数规则已经很强，因此不能以 99.32% 准确率宣称神经模型优于几何方法；负例少且删失多也限制结论。

开发消融使用种子 31 的六类布局，每类一个起点，共 36 回合。它们不与训练侧几何重叠；环形布局仍与验证侧几何重复，故整批明确标为开发数据，不得改称最终未见测试集。配置在运行前固定，结果无论正负均完整保存。

| 方法 | 最终覆盖率 | 覆盖 AUC | 重复移动比例 | 平均回合耗时 |
|---|---:|---:|---:|---:|
| gain_per_cost | 82.11% | 0.5043 | 10.96% | 3.37 s |
| gain_control | 82.12% | 0.5029 | 8.18% | 3.47 s |
| gain_semantic | 79.41% | 0.4708 | 8.67% | 3.33 s |
| gain_structure | 76.36% | 0.4502 | 7.52% | 3.90 s |
| gain_semantic_structure | 76.45% | 0.4585 | 10.17% | 3.99 s |
| gain_semantic_structure_rpn | 75.38% | 0.4491 | 6.34% | 3.56 s |

数值先对同地图起点平均，再对地图等权平均；本次每图仅一个起点。全部 36 回合没有碰撞。曲线阴影是地图间标准差，不是置信区间。原始几何基线没有 32 步目标时限，语义/结构的直接对照应使用 `gain_control`。

语义、结构和二者组合分别在 52、66、96 次选目标中改变了同一候选集上的几何排序；全模块运行累计调用 RPN 9,716 次。关闭开关后对应调用数为 0。全模块和无 RPN 的组合策略在六张地图上产生不同轨迹的数量见 `mechanism_report.json`，这些证据支持“已接入并影响决策”。

平均覆盖结果不支持新增机制优于几何基线：语义加结构的覆盖率为 76.45%，预算对照为 82.12%；再加 RPN 后为 75.38%。不能删掉单房间或大厅的退化结果。语义热点没有对应覆盖任务的真实价值定义，当前最大值奖励可能引导绕行；结构评分及部分观测区域划分也仍需在开发集分析。这些是待检验解释，不是已证明原因。

全模块 496 次目标中，180 次到达、11 次超时、305 次删失；因此只能将到达率 180/191 解释为已确定结果的条件到达率，同时报告删失数量。区域路径会随新观察到的障碍和足迹膨胀失效，不能把这些记录悄悄算成成功或失败。

## 验收与后续决策

续进记录：已完成本节后续的规则对照、开发诊断和 v1 冻结比较，见 [CPU 冻结实验报告](CPU_FROZEN_EXPERIMENT.md)。以下保留本阶段当时的验收与建议，原始开发数据不被正式测试替换。

本阶段新增 11 项机制测试；二维测试总计 26 项通过，旧评估完整性测试 16 项通过，共 42 项。覆盖：门洞切分及 ID 匹配、未知边界、语义视野隔离、开关调用及零权重一致性、评分实际生效、目标时限与删失、空候选回退、含转向的动作成本、冻结权重、实际输出日志及噪声语义的有限终止。依赖检查和相关文件语法检查通过。

另对本阶段全部 46 回合从逐步可见掩码独立重建覆盖率，核对语义记忆不越过视野、候选位于已观测自由格点、到达标签对应真实末端姿态、超时动作预算以及冻结权重哈希。结果见 `audit_results/2026-09-10/cpu_mechanism_verification.json`。已有历史资产与前两阶段结果保留；现有空间足够，没有删除数据或增加依赖。

下一阶段应先把当前结果作为开发基线，形成正式协议：

1. 测试地图按几何内容哈希隔离，同时检查与本次训练、验证、开发数据重叠；仅有少量几何变体的环形布局不能仅换种子便声称未见地图。
2. 保留原几何、预算对照和必要消融；新增“动作预算规则”的闭环对照，再判断小型 RPN 是否有贡献。现有证据不足以增加 UQ 复杂度。
3. 在开发集明确语义目标定义，检查结构权重、区域更新及大比例路径失效；任何修改在正式测试前冻结。若收益仍不成立，论文如实报告机制的适用范围及负结果。
4. 扩充独立地图和重复起点后才估计误差、成功率与计算开销；最后同步论文实验章节。当前合成语义、完美里程计和二维结果不能支持真实开放词汇感知或三维 SLAM 性能结论。
