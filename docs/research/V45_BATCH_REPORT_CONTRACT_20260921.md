# V45 开发批次汇总合同

实现为 `nso/batch_report_v45.py`，入口为 `scripts/report_development_batch_v45.py`。只读批次摘要、原始预约账本、永久启动收据和已保存的独立子进程输出，不启动仿真、不融合地图、不重算表面质量。

## 分母与状态

每份报告始终列出五个原协议槽位：R2 诊断，以及 A/C 各一组 G/S 对照。状态区分真正未启动、已提交启动但未预约、预约未完成、已终止但缺少完整验证、已有验证终点和证据不一致。启动或预约记录不能通过换输出目录消失；失败也不能从清单里删除。没有评分的任务保留空值，不插补为零，也不当作另一方法获胜。

R2 只用于进入自主批次前的诊断，不纳入 G/S 结果。批次摘要中的状态会同时保留，便于区分物理任务终止与后处理出错。完整且未返航的端点可以保留描述性质量值，必须同时标明 `task_success=false`，不能只挑成功任务形成比较。

## 证据绑定

报告不直接接受摘要内的得分。它首先核验历史摘要固定的 episode manifest、独立重算结果、离线评分结果三个 SHA，检查子进程退出状态、stdout/stderr 的哈希以及结果 JSON 与实际子进程输出的一致性。批次执行源码闭包也必须保持一致，包括后来的验证器与评价器源码。

随后由 V44 加载器再次核对原始 episode，检查原始预约、连续观测、公共合同、全部预测及源代码绑定。评分必须与同一 run ID、方法、场景、参考和完整预测对应；C_nav、Q、J_nav 均需在 [0,1]，乘积关系也须一致。有限解析夹具不具备真实开发实验资格。

这些摘要检查用于发现损坏或文件错配，并非第三方数字签名或抵抗所有源与摘要同时被重写的认证。完整性收据不等于方法有效性证据。

## 成对比较

只有 G 与 S 都有独立重算及离线评分通过的完整端点，且公共 graph/spec/workspace、全部运行源码、固定参考和噪声种子相同，才输出 S−G 的 C_nav、Q、J_nav 差值。公共 spec 摘要同时约束预算和传感参数。两分量的变化分别报告，不能用乘积遮盖覆盖率下降。

A/C 是两个开发父场景，不是独立留出测试集。报告仅给描述性成对差值，不做显著性检验，不生成置信区间，不自动宣称语义创新成立。代码测试中的合成正负差值仅检查汇总逻辑，不属于实验成果。

## 使用

```bash
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 \
PYTHONDONTWRITEBYTECODE=1 .venv-3d/bin/python -B \
scripts/report_development_batch_v45.py \
  --batch-summary <已有批次的 summary.json> \
  --output <新的汇总 JSON 路径>
```

输出禁止覆盖已有文件。对资源不足时的空批次摘要，报告保留五个未启动槽位及空指标；不能把这样的报告称为完成了五项实验。
