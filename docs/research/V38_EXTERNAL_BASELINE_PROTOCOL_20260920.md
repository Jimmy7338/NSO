# V38：设施建档外部基线比较协议草案

日期：2026-09-20。**状态：比较原则与分阶段执行设计；外部基线实验尚未执行，执行矩阵尚未封存。** 本页不改变 V35/V36 源码、指标、主实验 35/36 计数或已有结果。原剩余一次机会不自动用于外部方法矩阵。用户已要求补充主流方案对比；实现、调试和后续运行应在下述信息及预算约束下推进，不能先看测试结果再改变这些原则。

## 1. 两个问题与三种比较层级

问题 A：在共同表示、候选和执行器下，类型条件选向是否优于同样具有主动补看能力的几何策略及其他语义观察评分？问题 B：当引入成熟的原作者探索系统后，本文在设施建档任务中的整体权衡如何？问题 A 的结果不能回答问题 B。

|层级|拟比较对象|名称与能支持的结论|
|---|---|---|
|L1：共同 CPU 决策机制|现有强几何 G、现有语义 S；新增 SWAP 启发的已发现目标补洞／视角质量机制，及 VISTA 启发的任务相关视向覆盖机制|新方法必须命名 `SWAP-inspired/CPU`、`VISTA-inspired/CPU`，并逐项公开偏离。只比较共同闭环中的机制，不写“复现 SWAP/VISTA”或“优于作者完整系统”。这是最先可做的一层。|
|L2：原作者完整规划器的传感器／平台适配|固定 TARE 完整节点；资源允许再做 FUEL 地面适配|保留原规划核心，分别记录视场模型、ROS 桥接、地面约束、共享执行器和返航监管改动，名称含 `ground/RGB-D adapted`。能比较该公开适配系统；不能直接外推原论文全部平台与场景。|
|L3：原生作者任务与系统|TARE 原生 CMU 演示，或 SPP 的重复工业结构任务；FALCON/ActiveSGM/VISTA 原系统列为资源允许后的扩展|原生演示检验构建与运行忠实度。若表示、传感器和控制器不同，系统结果必须另表，不能同 L1 混排。SPP 只有在重复语义图输入真实存在时才纳入，不能在其机制无法触发的场景中故意把它设为弱基线。|

FUEL 官方 CPU 仿真路径已公开；FALCON 默认 README 仍包含 CUDA pointcloud_render，尚无本机纯 CPU 演示证据。ActiveSGM 与 VISTA 的原始后端有 GPU 依赖，VISTA 使用 ROS 2。论文选择理由和原始来源见 [V38 相关工作核查](/root/NSO/docs/thesis/V38_RELATED_WORK_AND_BASELINES_20260920.md)。

## 2. 信息授权必须在代码层可审计

各方法在各自执行轨迹上接收同一传感器生成模型；“同一观测”不意味着强行让不同路线收到完全相同的图像。相同历史与相同动作时，配对噪声／观测须可重复；不同动作只取得实际执行后的新观测。

|信息／能力|所有方法共同具备|额外限制|
|---|---|---|
|运动与观测|相同地面动作集合、机器人 footprint、相机外参、视场、分辨率、深度噪声、频率和曝光规则；相同初始位姿|禁止给几何法更窄视场、更差深度或更少观测。移动、原地转向、重复拍摄均按相同规则计费。|
|几何后端|相同已执行 RGB-D、同一位姿来源、同一 TSDF 参数和轨迹级重建输出|G 可使用已观测缺口、不确定性、可见性与视向历史主动补看。缺失语义不等于禁止补看。|
|公共先验|相同已公开安全图、任务边界、两种候选结构、设备参考系及评估区域定义|如沿用 V36 的公共候选 CAD／安全图，必须提供给全部方法并明确这是已知安全图上的建档；未知隐藏构型 h 仅评价器可读。|
|类别线索|各语义方法接收相同检测结果／受控概率；未知及拒识规则一致|不得让 S 有正确人工类别，而其他语义基线只能盲猜或被分配随机语义。不得用文件名、场景名、GT instance id 或隐变量作为识别输入。|
|无语义对照|相同公共结构模型及几何信息；类型分布采用冻结的无类别先验|可用实测几何更新后验，不可读 RGB 中的受控类型线索。保留 posterior 更新、预算规划和返航能力，避免同时删掉多个机制。|
|目标关联|共同的已发现目标关联或几何候选对象，不向任何方法免费提供隐藏目标位置|若为机制隔离提供公共目标 ROI，必须所有方法一致并单列“已发现目标条件”。如果语义影响检测候选生成，该实验须另立问题，不能混作纯评分消融。|
|预测与评价|候选评分可计算已观测地图上的射线、结构假设、代理质量；离线评价统一查询 GT|不准执行未选候选的 World/深度渲染/TSDF 来提前获取真实收益；不准将 GT F1 差值作为在线奖励或收益查表。所有实际调用保留计数。|

L1 共同候选池检验评分差异，同时移除了各作者算法的候选生成能力；报告必须说明这一点。若候选池只允许本文偏好的两个方向，结论限于该受限决策问题；不能称外部方法探索能力差。L2 应保留原规划器候选与路径机制，并使用共同安全执行器；拒绝和投影行为逐条记录。

## 3. 机制适配的最低忠实度

**SWAP-inspired/CPU。** 至少保留已发现目标的补洞与观察质量动机，使用已观测表面／占据图、投影视场、距离／入射角和未覆盖视向计算分数。不得把其替换成“最近语义目标”然后称 SWAP。所有距离、角度阈值与探索／检查切换规则在开发集确定并冻结。当前图中不存在可靠表面法向时，应记录输入不具备，不能用 GT 法向补齐。

**VISTA-inspired/CPU。** 保留任务相关性与视向多样性。设施建档查询设为所有预先规定的设施类别，统一等权，不能只选择对本文有利的一类。共同 TSDF 表示替代高斯地图、共同候选池替代原语义采样、CPU 可见性替代原渲染时，都列入偏离表。公开代码的语义聚合与论文文字曾有版本差异，必须选择固定提交的一种公式并写出，不能拼接较弱组合。

**SPP。** 有重复语义子图、可靠关系提取及已观察参考工位时，才允许推断尚未发现的同构结构。当前 type_A/B—服务侧先验不等价于 SPP 的重复子图预测。不能把本文的二元先验抄给它并冠名完整 SPP，也不能因当前场景未提供它必需的信息而宣称战胜 SPP。

**ActiveSGM。** 如后续增加熵机制对照，使用共同、具有不确定性的观测语义分布；不要给全部像素确定标签使熵人为退化为零。旧静态审查发现作者候选评分曾查询候选模拟深度有效性；本项目协议禁止这一未来观测输入，删除后必须注明差异。CPU 替代高斯渲染的版本只能作为启发式机制适配。

以上要求来自对直接前作的审查与当前信息隔离问题的设计判断，不是作者已证明这些 CPU 改写等价于原算法。固定旧代码审查见 [语义建档邻近工作](/root/NSO/docs/research/SEMANTIC_DOCUMENTATION_RELATED_WORK_GAP_20260915.md) 和 [SPP 审查](/root/NSO/docs/research/SEMANTIC_DOCUMENTATION_SPP_OVERLAP_REVIEW_20260915.md)。

## 4. 开发、留出与执行清单

1. **实现与接口阶段，零物理回合。** 给各适配器固定源版本、公式、参数和 CPU 依赖；使用已保存观测做输入完整性、禁止访问字段、可行动作与确定性检查。保存观测只能用于接口验证和决策诊断；未执行的替代动作没有新的 GT 收益，不能离线补造结果。
2. **开发阶段。** P00/P01、既有种子与 h 构型已被研究者多次观察，均标为开发／已见布局。各方法调参具有相同预先列出的尝试上限，并保存所有尝试；不按测试集最佳值挑参数。原作者推荐参数可作起点，必要单位／视场换算要记补丁。
3. **小规模机制桥接。** 拟在 P00/P01 × h0/h1 上配对比较 G、S 和两个 CPU 机制适配器；这是 16 条主轨迹，若逐条重放再增加 16 条重放，不能把它称为一次主实验。该数量是资源估算，尚未完成执行矩阵封存；不得由原剩余一次配额直接启动。只有新资源清单、每任务时长／磁盘上限、源码与配置 SHA、具体噪声种子、执行次序和输出目录封存后才可运行。
4. **独立确认。** 需要新布局时，先固定布局生成规则与适用条件（遮挡、互补观察、目标稀疏性、覆盖竞争），再生成并封存从未用于调参的布局及种子。布局数量在运行前按资源和开发方差确定；未填满这张表之前不能称“已预注册独立确认”。历史 P01 虽可作跨布局复核，不重新命名为未见测试集。
5. **一次冻结执行。** 按配对任务单位随机或轮换方法次序，避免机器负载偏差。源码／参数修改则形成新开发版本；不能在同一个确认结果内修到成功后只保留成功版本。

执行冻结清单须新增独立 JSON，列出 `protocol_sha256`、`source_sha256`、`backend_sha256`、`scene_ids`、`seed_ids`、`method_ids`、逐项任务及重放数量、`max_wall_time_s`、`max_output_bytes`、`min_free_bytes`、失败规则、开发参数尝试与冻结时间。当前本页只是设计协议，不声称这些字段已经具备。

## 5. 评价、失败与统计

主指标沿用冻结定义的 (J_5=C_{2D}F_{1,5\mathrm{cm}})，不得改变 V36 的网格采样、实例／区域权重、公共 ROI、表面裁剪或匹配距离来帮助某个方法。确认集同时报告 (C_{2D})、F1@2/5/10 cm 的 precision/recall/F1、(J_5)、路径长度、转向量、观察次数、返航、碰撞、覆盖资格以及运行时。5 cm 是主阈值，2/10 cm 为预定敏感性分析，不能挑最好阈值作摘要结果。不同算法的地图应由同一外部评价器重算，不能直接抄作者原论文的覆盖率、PSNR 或语义分割 F1。

若沿用 V36，必须保留其**全部**传感器噪声、42 动作任务预算、共同初始观测前缀、返航与覆盖规则；因此比较的是给定共同前缀后的有限预算建档。若为了 L2 原作者系统改用连续时间／距离预算或取消前缀，应重新给全部方法执行相同协议并单列结果，不把旧 V36 数值直接拼进新表。

失败进入全任务表：编译／缺依赖写“未能执行”并与运行中失败区分；超时、碰撞、动作非法、未返航、预算超支和覆盖不足均保存原因与截止时已有地图。报告所有已启动任务及成功率，不能仅取成功回合。主文同时展示原始 (C,F1,J) 与任务资格。若需要失败计零的效用，另记为 (J^{\mathrm{qualified}}=\mathbf{1}_{\mathrm{qualified}}J)，在运行前冻结；不得在结果出现后用它替换原始 (J)。外部过程崩溃导致无有效地图时该事实单列，不能填一个伪造低分冒充已评价模型。

**统计单位是独立布局／任务生成单位。** h0/h1 是同布局的配对构型，噪声重复是布局内重复；相同轨迹的 42 个帧、多个物体、多个阈值以及验证重放都不是独立样本。先在同任务内计算方法差，再按布局等权汇总；相对增量和绝对增量并列。当前两个布局只给描述性均值与逐构型结果，不给显著性星号或把 8／16 个执行计数写成独立场景样本量。

独立布局数量足够且运行前确定时，可给布局级配对 bootstrap 区间或配对置换检验，并说明抽样单位、次数与随机种子。小样本不以帧级重采样缩窄置信区间。四种方法的多重比较须预先指定主对比 S−G 及 S−各外部机制，其他为探索性，避免逐阈值逐布局挑显著结论。

运行时在相同 CPU 线程和内存配置下记录，区分语义前端、地图融合、候选生成、评分、求解、执行／等待及端到端总耗时；报告各阶段中位数与 p95，同时保留冷启动和预处理成本。无 GPU 版本与 GPU 完整系统的耗时不可不加硬件说明并排宣称速度领先。共同 TSDF 减少了后端差异，但不能把其耗时从只有本文的总耗时中扣掉。

## 6. 图表与最终报告约束

主结果表每行必须有方法的 `original/adapted/inspired` 标识及真实执行状态。未执行写“—（未执行）”，不填估值、排名或最优加粗。开发与确认、原生与适配分表。图采用配对散点／连线、同尺度重建对照、覆盖—质量平面和成本曲线；用实测点支持机制，避免仅用均值柱形图掩盖零增益与失败。阈值、坐标单位、独立样本单位及误差线含义写入图注。

预期允许的结论包括“当前构型下无增益”“几何方法已经足够”“预算下质量改善但覆盖／运行时代价增加”“对 SWAP-inspired/CPU 无优势”。任何一种都保留并解释适用边界。外部比较的作用是确定本文相对于真实强方法的有效条件，不是给已有正结果寻找必输对手。
