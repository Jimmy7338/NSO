# V12 大规模多资产开发准备结果

V12 已解除 V11.1 的两个结构限制：新特征接口接受 1--24 个实测资产，并以固定 20 维表示“候选目标资产 + 其余资产集合”；候选容量按 `coverage_slots + rotation + 2 * asset_count` 计算，12 个资产需要 29 个槽位，不再沿用固定 6/12 槽导致资产被系统性截断。

单元验证共 6 项通过：1/2/5/12/24 资产维度一致；资产与审计数组共同置换并重映射目标后逐位一致；标签翻转保持几何向量不变并反转全部有符号语义尾部；无目标覆盖候选不依赖资产顺序；非法资产数量和目标索引被拒绝；候选容量公式通过边界检查。浮点集合归约采用固定排序，使独立重放哈希不受输入枚举顺序影响。

## 运行时候选预检

D12-00 首次预检保存在 `eval_results/semantic_gain_v12_candidate_smoke_20260911`，并按失败处理。前缀走访了 8 个设施的实际前视位置，运行时几何聚类得到 11 个片段；按真值资产数计算的 21 槽上限仍截掉 3 个 deep 角色。这证明候选容量不能依赖场景真值或固定资产数，必须依据可观测片段动态分配。

修订预检使用 V12 声明的 24 资产上界，因此预留 53 槽，不改变候选排序或评分。实际 11 个片段中，8 个含可见标记并与 8 个设施对应，3 个是不带标记的短墙面片段。共生成 23 条候选，8 个语义资产均有可行候选，`omitted_by_cap` 为空；两个墙面片段的 entry/deep 因没有合法投影视角而明确记为 missing，不被伪装成资产视角。370 个付费共享前缀动作后仍保留 350 动作预算。

相同脚本、源码与协议独立重跑两次，`result.json` 均为 SHA-256 `3ce7e3a6a3ebb23606549eb2c8bff24a31280cf2b7865bf335b451338ae4c7d7`，逐字节比较通过。通过记录位于 `eval_results/semantic_gain_v12_candidate_smoke2_20260911` 和 `eval_results/semantic_gain_v12_candidate_smoke3_20260911`。该预检没有执行任何候选，`planner_outcomes_generated=0`。

## 第一组严格物理分支

最初为加速分支采集，尝试对包含 Open3D TSDF 的前缀 mapper 使用 Python `deepcopy`。顺序结果从第二个候选开始偏离独立计算；原地重复扫视被错误记录为 +1.342/动作。单独的 0--8 次重复扫视诊断表明第二次扫视实际为 −0.002853/动作。改为每条候选建立全新 mapper 并重新融合全部 375 个前缀帧后，候选 4 恢复为完全相同的 −0.002853/动作。证据见 `audit_results/open3d_tsdf_branch_isolation_20260911/verification.json`。所有使用深拷贝的分支目录已增加 `INVALIDATED_DO_NOT_USE.md`，不得训练或引用。

修订采集器在 D12-00 对 23 条候选逐条完整重放，23/23 无碰撞且安全返回；8 条在最新观测使原路线失效后切换到安全返程，均显式标记。固定 N/G/S/X 全部选择 `coverage_total_3`，其真实单位动作联合收益为 0.077875、在 23 条中排第 8；手工语义评分在该场景没有产生选择差异。

前 5 条严格分支随后与早先独立的 5 条全重放逐字段比较，5/5 完全一致，规范 JSON SHA-256 均为 `ac5407cc1846dcd55a3146f2cdd5464bd5d2eb476b2b2136a57c12acbcc6e595`。复核记录见 `audit_results/semantic_gain_v12_strict_branch_repeat_20260911/verification.json`。

8 个带类别标记的资产中，复杂类别相对简单类别的平均单位动作联合收益，entry 为 0.073651 对 0.052400（+40.6%），deep 为 0.076398 对 0.060950（+25.3%）。复杂类别的路线同时产生更大的二维覆盖增量，因此这个单上下文差值仍混入资产位置与沿途覆盖，不能称为语义因果收益。它只说明严格数据中存在值得跨随机布局检验的条件结构。有效目录为 `eval_results/semantic_gain_v12_fullreplay_branches_D12_00_20260911`。
