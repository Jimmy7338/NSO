## 实例接口的进展与边界

新账本只接收付费 RGB、深度、内参和相机位姿，加上帧号与付费步骤；严格拒绝额外身份或 GT 字段。它从人工色码连通区域及测量深度生成位置锚点，通过几何位置关联实例，不用类别决定实例对应。不同设施的类别证据不会再进入一个全局冲突状态。

至少两个相距足够远的观察位置才能激活类别先验；重复帧、微小位移以及重复反馈不能无限累积置信度。类别冲突保守回退几何先验；持续错误类别的自动恢复策略仍待研究。几何反馈入口绑定已接收的付费帧及实例，但实际 RGB-D 残差产生器和完整运行器尚未接入，不能称为已经完成真实残差反馈闭环。

旧数据兼容检查只解码四个传感数组，检查其文件 SHA 与 V39 封存一致，不解码包内 metadata/semantic/owner。四条旧轨迹各发现一个标记实例；因此这项检查只验证旧单设施数据能接入新接口。多实例能力的当前证据来自解析构造测试，不是新的多设施任务实验。人工色码检测不能写成自然实例识别网络。

## 场景准备与交叉审查修正

已创建 **42 个父场景预留**：6 个开发父、24 个主测试父、12 个边界父。六个开发配置覆盖机柜、货架、混合设施、几何充分中性场景、覆盖压力及语义失配。网格、粗导航图、实例清单和评价表面集合均为 pending，不声称已生成 42 个场景或已完成内容去重。

36 个正式测试父的随机 seed 仅保存在本机受限权限 escrow，公共目录只有承诺摘要；私有文件被 Git 忽略。公共复核没有打开它。该安排是可追溯的流程隔离，不是第三方盲法。seed 未同时冻结尚未实现的生成器，正式测试仍需完整冻结生成器和实际资产。

独立代码审查发现并修正三处合同问题：

1. 场景先验原本允许零项，而实例账本要求正支持；现在统一每项至少 `1e-9`。
2. pending 场景原本可能携带任意 materialized 公共图引用；现在要求公共图同样 pending/null。
3. 仅检查键不足以防止偷偷改预算、相机或先验；增加与 protocol 默认值的绑定及 catalog/spec 联合检查。主线集成必须传 `protocol`。边界预算例外只允许使用单独预声明且绑定协议摘要的 sidecar，本轮没有为未来测试父生成例外。

原场景准备目录与 seeds 保留不动；修正源码、测试与旧公共配置复核记录另存在 `audit_results/v40_scene_contract_amendment_r1_20260920/`。随后补齐了行和容差下归一化概率可能越过下界的跨模块边界测试，最终修正保存在 `audit_results/v40_scene_contract_amendment_r2_20260920/`。

## 资源和下一阶段

持久磁盘当前约 0.6 GB 空闲，未达到计划中启动新实验批次的至少 10 GiB 储备。本轮仅生成有上限的小型合同与回放文件，浏览器和现有 Python 包使用内存盘。没有删除旧实验唯一证据、Git 历史或其他项目文件。内存盘不是持久证据库，不能据此视为正式批次存储门槛已满足。

下一阶段按以下顺序推进：

1. 先实现六个开发配置所需的多设施几何生成器、共享粗导航图和独立评价表面构建器；每个实例由付费观测发现，GT 实例清单只供评估。
2. 将新实例账本接入 OV-SDF，并连接 STGHP 的跨设施预算分配、RPN-UQ 的视角选择与 IGCR 的付费观测残差更新；从动作 0 自主选择并保留实际返航成本。
3. 实现覆盖与实例宏平均 F1 的分项及联合指标，先用可解析几何验证水平/竖直外表面、漏检实例分母和轨迹独立性。
4. 在持久空间门槛满足后，仅对开发父运行小批试点，验证观测—残差—规划—重建—评分闭环；通过后冻结方案和生成器，再激活主测试与外部方法批次。

当前结论是 **P0 工程和证据展示已完成**。本轮新增 World、完整规划器调用、真实传感轨迹、重积分、质量评估、训练和现场测试均为 0。语义优势的实证仍来自此前受控虚拟实验；多设施、跨场景和完整系统优势是后续需要检验的假设。
