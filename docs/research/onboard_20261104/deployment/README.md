# Static deployment-source staging — not a deployable distribution

This is a read-only snapshot of the Nov 04 physical integration sources and selected ROS source dependencies. It is not a turnkey or tested fresh build, and it does not authorize or start robot movement. It omits model weights, compiled drivers, ROS build/devel trees, Python environments, logs, credentials and recordings. The paper/replay archive is separate. `hybrid/` retains the entry script, all local runtime Python modules and dashboard assets, configuration, launch files, fixed masks, bridge and selected vendored implementations. `hybrid/start_verified_stack.py` is the actual CSM recovery script: merely including it does not make it safe to execute on another robot.

The launch chain is `run_hybrid.sh` → `runtime/mission.py`; CSM recovery separately launches the ZED RGB-D camera, lslidar + CSM + gmapping, `csm_odometry_bridge.py`, `hybrid_sensor_bridge.py` and move_base. The mission dynamically loads `visual_velocity_adapter.py`, and, when commanded, the separate native `nso_scout_attended_node`; the ordinary ROS navigation collision layer and hardware watchdog/protection remain distinct from research-policy selection. Exact recorded S40 configuration, navigation contract and source hashes are under `provenance/`. The current fixed IMU mask is `hybrid/config/assets/fixed_imu_left_curve_20261031/` (its calibration is a physical setup assumption). Preserve actual machine calibration and do not infer extrinsic accuracy from file presence.

`hardware_sources/` includes only the local native driver and SDK 0.8.0 (Apache-2.0). Other dependencies are not vendored; see DEPENDENCIES.md. The source paths for lslidar, move_base, Scout description and ZED wrapper/nodelet match the old `/home/ouc/scout_nav/build/CMakeCache.txt`; that identifies the configured sources, but does not prove current source files match compiled binaries. No binary/source equivalence or clean build is claimed. The `laser_scan_matcher` and CSM source was not located in the local source workspace; this system used the distribution packages listed below. The camera needs a separately installed proprietary ZED SDK, CUDA and compatible GPU/driver. Its camera calibration, serial, CAN setup, time synchronization and network topology are physical-system-specific. Scout description and visual meshes are absent; some visualization/URDF consumers require them.

The native driver CMake requires catkin, roscpp, geometry_msgs, std_msgs, Threads and explicitly supplied `NSO_UGV_SDK_INCLUDE_DIR` and `NSO_UGV_SDK_LIBRARY`. The snapshot SDK includes sources, CMake and license; a fresh build must supply libasio-dev and build the SDK first, then configure the native package against its resulting include directory and library. A matching ROS Noetic environment must supply lslidar, ZED interfaces/wrapper, Scout description and navigation packages against their declared package dependencies. Consult each package.xml/CMakeLists and vendor installation instructions. These steps are a source map, not a verified build recipe: SDK binary ABI, CSM source/package availability, ZED proprietary SDK, GPU stack, robot firmware and hardware calibration have not been reconstructed or tested.

Recorded local versions: Ubuntu 20.04.6, ROS Noetic, system Python 3.8.10; science Python 3.12.15 with numpy 1.26.4, scipy 1.11.4, torch 2.6.0+cpu and ultralytics 8.3.200; `ros-noetic-csm` 1.0.2-2focal.20250426.011722, `ros-noetic-laser-scan-matcher` 0.4.0-1focal.20250521.032611, `ros-noetic-gmapping` 1.4.2-1focal.20250520.021424, `ros-noetic-move-base` 1.17.3-1focal.20250521.022443, `ros-noetic-navigation` 1.17.3-1focal.20250521.023218, `ros-noetic-robot-state-publisher` 1.15.3-1focal.20250520.020302, `ros-noetic-xacro` 1.14.20-1focal.20250519.235746. Installed ZED SDK config declares 5.0.0; local wrapper package declares 3.5.0. These are observations, not proof of compatibility in a clean installation.

`provenance/MODEL_MANIFEST.json` provides the YOLOE and MobileCLIP upstream URLs and SHA-256 values. Prompt embeddings have no source URL; the local generation script is included and requires the exact models, prompts, preprocessing and library versions, with reproduction of its hash still unverified. Model weights are not included. `run_hybrid.sh`, `start_verified_stack.py`, `reference_transport.py`, and configuration files contain absolute local paths; adapt and review them rather than assuming portability. Their loopback ROS master, camera serial and network settings identify this particular machine setup.

Licenses and upstream provenance need review before distribution: the local lslidar driver package.xml says `TODO` for its license and no corresponding license file was found in the copied lslidar tree. The native package declares BSD-3-Clause in package.xml; verify actual grant and applicable SDK terms. Other copied packages retain their source license files where present. Third-party ROS packages, ZED SDK and model assets have separate terms. The unresolved lslidar source is excluded from this public package.

Static validation: 86 hybrid Python files parsed by Python AST, 8 launch XML files parsed and `bash -n` passed for the entry script. The SDK library and native node were subsequently compiled on the current machine only; see native_build/receipt.json. No executable, ROS, or motion command was run. This validates syntax only, not dependencies, hardware safety, source/binary fidelity, permissions or behavior.

Source identity boundary: comparing the 107 files in the S40 `provenance/source_manifest.json` against the current workspace yielded 106 matching SHA-256 hashes and one difference: `nso_bridge/nso_bridge/shared_observed_prefix.py` was `214b093c2e7730529ec11e8aaf9ecd02f1c12c32e23566572222bedb21993378` at S40 and is `8865b6c303972c3e39d03515c5cd5361b91e740d6ef00a024aa2b0cafe557568` in this current snapshot. The recorded old file was not found by local filename search. Therefore this bundle is a current deployment-source snapshot, not a byte-exact reconstruction of the original S40 runtime; the operational impact of that change is not inferred from the hashes. The unmodified actual S40 manifest is retained for independent audit.

A limited credential-pattern scan of the staged files found no private-key headers, common GitHub/AWS token formats or quoted credential assignments. It is not a guarantee that all secrets or identifying data are absent; the snapshot includes a camera serial number and local filesystem paths, which require consideration before any external distribution.

The original native build receipt references dynamic_section.txt, which is not included in this minimal package; ldd.txt is included. The published build.sh defaults to this package directory, a path-only adaptation from the original tested script.
