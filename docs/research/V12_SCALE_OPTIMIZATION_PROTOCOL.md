# V12 大规模多资产语义规划优化契约

## 根因与版本边界

V11.1 的独立正结果来自两个设施、基础覆盖后的三维补看。它不能直接扩展到用户提出的大规模语义场景，因为 `candidate_features()` 和 `_scores_v11()` 都要求资产数组恰好为 2；固定候选上限还会在资产增多时优先截掉后续资产。场景放大而不修改表示只会造成异常或候选缺失，不构成规模实验。

V11/V11.1 源码、模型和 F00--F11 结果继续冻结。V12 使用新模块 `nso/semantic_gain_v12.py`，不回写既有证据。

## 保留的完整方案结构

ANS 的全局/局部层次及四个模块职责不变：OV-SDF 提供带置信度的可消耗实例语义，STGHP 在区域覆盖骨架上安排局部补看，RPN-UQ 负责可达/观测风险和低置信回退，IGCR 用实际新增观测修正候选收益。V12 只改变 STGHP/IGCR 之间的候选收益表示和大场景候选配额。

## 新表示

每条候选保留一个显式目标资产，其余资产通过固定排序后的和、均值、最大值归约。这样 1--24 个已测资产始终产生 20 维输入，资产顺序变化不会改变特征或重放哈希。无显式目标的覆盖候选对全体资产使用对称汇总。

前 12 维为所有方法共享的几何、代价、资产数、目标/非目标视孔与实测支撑；后 8 维为类别符号、置信度、剩余观测欠账与目标/集合机会的交互。同容量几何网络以 8 个标签无关的二次特征替换语义尾部。标签置换必须保持几何向量不变，并使有符号语义尾部反向；低置信度必须回退到几何网络。

这不是把大场景真值压入规划器。输入仍只来自决策时刻的候选预测审计、RGB marker 观测、已测实例范围和历史视孔支撑；分支执行后的 GT 指标只能作为离线训练目标与外部评价。

## 场景和实验矩阵

开发清单为 `configs/virtual3d/semantic_gain_v12_scale_development.json`，含 8、10、12 个设施和 35.6--73.2 米的长通道布局，改变设施间距、复杂比例、隐藏部件以及相关、独立、反向语义关系。每个物理上下文运行 aligned、shuffled、absent 三种语义干预；它们必须共享几何、深度、雷达、噪声和起点。

候选配额按当前已测几何片段数计算，至少覆盖若干几何覆盖候选、一次原地转向以及每个片段的 entry/deep 两种观测；在当前 CPU 预检中可先按24资产上界保守预留53槽。若预算或可达性使某候选缺失，必须记录具体原因；不得用固定 6/12 候选上限系统性遗漏某些资产。几何聚类产生的无标记墙片段应保留为可审计的对象性误差，并通过共享的二值对象性基线处理，不能只对语义方法使用真值对象ID删除。

主表至少包含学习语义、同容量几何、质量感知 NBV、固定语义、覆盖层次和共享传感器适配后的官方 TARE。所有方法共享点云/位姿输入、起点、动作模型、路程或时间预算、返回规则、重建后端和 GT 评价器。

## 开发门和未来确认

开发阶段先检查：任意资产数特征有效；置换不变；语义交换保持几何不变；候选资产覆盖完整；无 GT/未来结果进入决策；规划时间和内存在最大开发场景可接受。随后才执行候选分支、训练 V12 模型和闭环开发。

模型、输入守卫、候选规则、预算和统计门冻结后，再创建从未运行的确认清单。确认必须同时满足：相关语义中联合指标优于同容量几何与质量感知 NBV；正确标签优于 shuffled；absent 与低置信回退匹配几何；独立/反向关系不出现不可接受退化；二维覆盖、三维 F-score、路长、碰撞、安全返回和规划耗时全部报告。覆盖压力层无增益也必须保留，不能用有利子集替换。

当前完成的是新表示实现和开发契约，不是 V12 效果结论。
