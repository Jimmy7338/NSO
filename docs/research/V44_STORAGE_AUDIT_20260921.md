## 审计结论

- 主机视图导入成功：NumPy 1.26.4、SciPy 1.11.4、Open3D 0.19.0、Matplotlib 3.8.4、Shapely 2.1.2。
- `.venv-3d/lib/python3.12/site-packages` 指向 `/dev/shm/nso_v39_python_packages`，主机目标存在。普通隔离 shell 所见的空 `/dev/shm` 属于另一个挂载视图，不能作为依赖丢失证据；无需重装。依赖导入与实际运行应使用能读取主机内存盘的既有执行方式。
- `storage_report_v41` 实测持久 ext4 可用 **7,942,967,296 B**，原门槛 **10,737,418,240 B**；缺口 **2,794,450,944 B**。这是本次审计时间点快照，启动时仍须重新检查。
- 原始公式为 `max(10 GiB, 2 × expected_batch_peak_bytes + 2 GiB)`。当前峰值声明 402,653,184 B，因此 10 GiB 项占优；没有更改、旁路或降低公式。

## 无损去重与 Git 压缩可能性

只读元数据扫描显示，`eval_results` 已有 162,952 条路径使用硬链接，`audit_results` 有 956 条。既有 V19/V20/V15 去重收据进一步证明历史上已进行多轮精确去重。

跨 eval/audit 对所有同大小、不同 inode 文件进行元数据筛选：假设所有同大小文件都相同，理论逻辑节约上限仍只有 **1,534,856,206 B**；这个上限没有内容验证，不能当作可释放磁盘量。仅对 ≥1 MiB 组做 SHA-256 验证，发现 **27 组**内容相同，理论逻辑节约 **70,277,074 B**。它们仍属于证据文件；如后续采用硬链接，必须保留全部路径与内容、核实所有 inode 别名并禁止就地修改。本轮未进行任何替换。详见 `duplicate_audit.json`。

`git count-objects -v` 报告 38,388 个 loose 对象，占 2,006,360 KiB；一个 pack 占 3,139,178 KiB，`prune-packable=0`。没有可直接删除的已打包重复 loose 对象。另发现两个 Git 暂存对象，共 1,508 KiB，未删除。完整重新打包可能增加压缩率，但收益及临时峰值尚未测定，不能将全部 loose 对象大小视作可释放量，更不能以删除历史换空间。
