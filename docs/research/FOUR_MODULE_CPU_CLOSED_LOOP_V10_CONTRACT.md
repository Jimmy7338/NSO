# V10：原四接口真实 CPU 闭环接入合同

设计日期：2026-09-11。状态：**待实现的工程合同，不是运行或性能报告**。本合同只读取当前接口及已固定的算法源，不读取 V9.1 部分未来指标、不修改任何正在执行的源码或协议。V9.1 的完整执行、回放和效果判定按它自己的冻结规则完成；此处不为其改变门槛。

目标是让实际 `NSO_Components` 与 `NSORuntimeIntegration` 管理的 OV-SDF、STGHP、RPN-UQ、IGCR 四接口参与每个真实 CPU 观测—规划—执行—反馈周期，保持 ANS 全局／局部两层。新入口不能直接调用独立实验评分器绕过四接口，再把调用日志补成“完整架构”。

## 2. 兼容边界与数据所有权

保留 `NSO_Components.initialize`、`update_semantic`、语义读取、拓扑更新／选择／重规划、UQ 预测、`compute_reward`、场景重置及 `NSORuntimeIntegration.observe/choose_goal` 的原调用方式和返回类型。允许新增可选关键字及辅助状态绑定方法，不删除旧入口、不新增一个绕开四模块的平行策略器。建议辅助接口为 `bind_sensor_packet`、`get_selected_option`、`assess_local_action`、`plan_return`、`observe_outcome`；它们分别属于现有管理器和四模块职责，并非第五个创新模块。

一个场景只能有一个权威地图后端和一个权威动作计数器。每个传感器包最多融合一次；四个模块读取同一地图版本，不能各自重复融合同一深度帧来增加点数、置信度或奖励。建议由 runtime 持有共享地图后端，`update_semantic` 消费该次观测的真实标签支持与只读几何快照，更新自己的结构响应状态。完整观测包通过辅助绑定提供，原 RGB 参数仍用于兼容与一致性检查。

### 必须有明确类型的数据

|记录|最低字段与约束|
|---|---|
|`SensorPacket`|`scene_id, episode_id, frame_id, timestamp_s`；[RGBDFrame](../../utils/rgbd_contract.py) 与 PlanarScan；标记／识别来源、位姿来源、可选协方差；本次动作编号、实际碰撞／到达／结束事件。RGB、深度与标签必须对齐，深度为米，无效像素为 0|
|`GridTransform`|地图坐标系、分辨率、原点、行列方向及世界到地图变换；统一 `world_to_cell/cell_center_to_world`。不能混用 ANS 的正向行索引与当前 CPU 世界从上向下的行索引；米、厘米、角度和弧度均在边界转换|
|`MapSnapshot`|`map_version, sensor_frame_id`；占据三态未知／空闲／占据；相机已见掩膜；实际测量点、法向／视角支持、类别支持来源及 TSDF 状态引用。不得出现真值网格、真实资产框、可达真值掩膜、未来可见面积或评估 F1|
|`SemanticResponseState`|稳定观测对象／表面组 ID，实际点支持索引，观测尺寸与方向，类别票数／缺失状态，先验来源及版本，已观察与假设部分的分离，候选条件响应分解。跨更新对象关联不能读取仿真真实对象 ID|
|`Option`|`option_id, parent_node_id, target_cell, target_heading, map_version, feedback_version`，局部动作／状态，去程成本、到达动作、当前已知返程成本、固定任务锚点、完整计划总成本、全部分数与选择理由|
|`FeedbackEvent`|前／后地图版本，真实动作编号与成本，新增观测支持、旧支持质量变化、已执行相机位姿、到达／拒绝／失败／终止原因，IGCR 各分量及单位，下一轮消费位置。没有实际执行的计划返程观测不得入账|

日志可以记录实验上下文名作追踪，但评分输入中不能用该名字推断资产类别或场景规律。评估器可以在独立旁路读取真值计算最终指标，输出只能进入结果文件，不能返回规划或奖励接口。

## 3. 四模块内部接入责任

### OV-SDF：实际类别证据与条件响应

CPU 首版允许选择明确的 `observed_rgb_marker_prior` 后端，通过原接口输出语义通道和丰富的结构响应状态；无需为了通过接口测试下载不可用的大模型。`use_open_vocab_semantic` 作为旧开关名可以兼容，但运行摘要必须分别给出 `interface=OV-SDF`、`semantic_source=rendered_rgb_marker`、`open_vocabulary_active=false`、`learned_response=false`、`calibrated_response=false`。

第一轮接线迁移沿用[已声明的先验](../../nso/competition_prior_v8.py)，不根据正在执行的 V9.1 部分指标改类别权重。尺寸、前后方向和对象分组只来自当前测量；未观测结构明确标为假设。`get_sem_density` 仅为原地图／网络通道和可视化投影；STGHP 必须同时收到组级条件响应，不能把一个类别数值较大的格子当成“更值得看”的完整推理。

缺失类别应走明确的类别边缘回退；正确、交换、缺失解释都保持原 RGB-D、几何支持和共同候选集合不变。若之后启用自然视觉或开放词汇后端，需另外验证标定、延迟、检测／类别错误和可用状态，不能继承人工标记的准确性。

### STGHP：全局任务与局部选项分离

全局层维护区域／资产组节点、已知可行连接、剩余观察潜力和任务预算，选择一个明确的局部观察选项；局部层执行该选项的路径和目标朝向。单房间 CPU 场景可只有一个全局区域节点，但日志必须说明这一退化，不能把两个目标列表称为已验证复杂房间拓扑。

`choose_goal` 继续接收原 ANS 提议，并记录提议来自真实加载的 ANS 策略还是显式 CPU 提议后端。若暂用替代 CPU 提议器，只能宣称 ANS 两层接口兼容闭环，不能宣称原训练权重及完整主程序已验证。不得在 PPO 训练期间修改其采样行动后仍用原行动的 log probability 更新；首轮接线使用评估模式，不训练或暗改原策略分布。

二维返回格点仍供旧接口使用，完整 `Option` 由 scene 对应的 sidecar 保存。局部执行必须消费其目标朝向、版本、返程锚点和成本；不能只走到同一格点就宣告相机观察完成。

候选数量取决于实际可行性：共同基础候选加真实可达的观察方向，缺失原因保留。新 V10 实现需把硬编码“两个对象、48 动作、返生成起点”改成内部参数化约束，并以独立路径检查验证；这属于下一版真实算法改动，不能追溯修改 V9/V9.1 已冻结的路线。

### RPN-UQ：确定性执行门禁与概率能力分开

将[现有执行保护](../../nso/execution_guard_v8.py)作为 RPN-UQ 接口内部的确定性可行性后端：每个支付动作之前验证当前位置和下一位置的完整机器人足迹，以及执行后仍有在剩余预算内回任务锚点的已知安全路径。未知区域不能被清成空闲，当前足迹不安全时不得伪造逃逸通道。

旧 `predict_reachability_uq` 在没有兼容权重时继续返回 `None, None`。不能为“接口看起来有输出”而把可达掩膜当成成功概率、把 EDT 距离当方差，或置零方差声称确定。局部可执行结果由辅助 `assess_local_action/plan_return` 返回，并把 `backend=deterministic_observed_grid, probability_available=false, calibration_verified=false` 写入摘要。

以后若接入学习 UQ，仍保留共同的硬安全门；模型训练和校准需新数据协议。MC 方差本身不等于失败概率，也不替代返程成本核算。当前地图与位姿有误时，已知栅格证明不保证真实运动零碰撞，实际失败照常记录。

### IGCR：支付后反馈必须改变后续状态

`compute_reward` 在每个真实动作后的观测上调用一次，首帧只初始化。V10 的 IGCR 内部持有每回合 `FeedbackLedger`：支付成本、实际相机位姿历史、固定旧支持及质量变化、已获得的观察支持、选项完成／失败状态。其返回的 `parts` 明确区分新增二维面积、测量支持代理、旧支持质量有符号变化、代价与终止原因；不将全场评估 F1 或真值新增面积混入在线输入。

第一轮接线可保留既有标量奖励作兼容，但仅打印该标量不构成反馈接入。STGHP 的下一轮响应去重与可用预算必须从这个实际反馈账本读取，决策日志必须引用被消费的 `feedback_version`。例如，候选未来孔径代理只能扣除**实际已执行**相机历史中的支持；已经过去的出发计划、取消的返程或未执行视点不能计作完成。已有孔径模型仍只是几何代理，不能将其账面减少量命名为真实新增面积。

把最新测量与未执行期望相分离：若运行后没有看到预期的新支持，应保留“无进展／预测偏差”反馈，不能因为计划选过该设备就自动将它标成完整重建。旧支持误差改善必须固定比较支持集，支持集变化另列；若采用仅观测可计算的质量代理，应在新协议中先固定定义，不声称它等于真值 F1。

`fresh_mask` 至少满足 $M_{\rm fresh}\subseteq M_{\rm explored}\cap\neg M_{\rm visited}$，并保持所有模式一致。若没有经过建模的占据先验／后验，不调用熵代理为条件互信息。首轮不宣称 IGCR 已用于 PPO 训练；若后续训练，需额外核对 reward 真正进入 rollout、终止 mask 和原行动分布。

## 4. 必须实现的完整时序与预算不变量

固定任务锚点 $h$，总支付预算 $B$，第 $t$ 个真实动作后剩余 $b_t=B-t$。每个动作 $a_t$ 的已知可行性至少满足

$$\operatorname{footprintSafe}(x_t,M_t),\quad
\operatorname{footprintSafe}(x_t^+,M_t),\quad
1+d_{M_t}(x_t^+,h)\le b_t,$$

其中 $d$ 是包含朝向恢复和转向成本的当前已知安全图最短路径长度。新观测可能改变 $M$，所以每个动作前都重算相关条件；上一轮保证不能跳过最新地图检查。

一个完整周期应按下列顺序发生：

1. 接收并校验真实 SensorPacket；验证时间、坐标和动作编号，地图只融合一次；终止帧也完成此步。
2. 通过原语义接口更新 OV-SDF 的观测条件状态。IGCR 对刚结束的真实动作产生并保存 FeedbackEvent；首次无前动作时只初始化。
3. STGHP 更新区域／资产状态、实际支持去重和剩余预算。正在执行的选项继续有效时交给局部层；到达观察目标、选项失效、地图拒绝、进展条件或剩余预算触发时重新做全局选择。
4. 全局选择产生带完整成本、目标朝向和固定返程锚点的新 Option；没有正的可用观察机会但存在返程时进入返程模式。不能因第一条路线结束就直接把地图保持到整个任务预算结束，却将它称为完成剩余预算规划。
5. 局部层只执行一个通过最新 RPN 门禁的支付动作，等待真实结果后回到步骤 1。执行拒绝是无动作事件，不能调用环境 `step`、生成免费传感器帧或重复奖励。
6. 锚点返程完成、预算耗尽或不可恢复停止时，先保存末帧地图、最后 FeedbackEvent、实际成本和终止状态，再结束回合。只有这些记录齐备后才重置四模块、共享地图、选项、反馈账本、位姿缓存与回合计数。

允许到达目标后从当前位置继续选下一个目标，而不要求每个选项都实际先回锚点；但所有候选都须保留同一任务锚点的返程储备。用于评估计划的预期返程观测，在尚未执行时不得计入 IGCR 已获收益。V10 最终策略因此是一条真实的新闭环轨迹，不能从 V9.1 独立分支拼接出不存在的性能结果。

终止包必须与 `episode_id/action_id` 对齐。若环境自动重置而缺少 terminal observation，应修复环境包装器或显式报未获得末帧；不能拿下一回合首帧、上一步帧或额外零成本观测补齐。预算终止时尚未回锚点属于失败，不可通过重置把它消失。

## 5. 必须可追踪的调用日志

每个模块事件至少包含 `run_id, episode_id, scene_id, module, method, call_id, parent_call_id, frame_id, action_id, map_version, feedback_version, input_digest, output_digest, capability_status, elapsed_ms`。预算日志同时记录计划成本、实际成本、返程余量、拒绝和终止原因。

全局决策日志额外保留完整公共候选清单、每个方法的分数分解、类别证据来源、共同项、类别边缘项／条件项、最终候选及并列处理。局部动作日志引用真实全局 `option_id` 与 RPN assessment ID；反馈日志引用实际已执行 action ID，下一轮全局决策引用该反馈 ID。把这条来源链串起来后，才能说明四个接口共同控制了一次运动。

`get_summary` 保留旧字段，并补充每个模块的真实后端、权重／先验版本、是否已训练、是否已校准、是否收到有效输入、调用次数和是否被后续决策消费。配置开关为真与模块实际有效要分开；不得用预设的“四模块 enabled=true”代替运行证据。

## 6. 接线验收必须证明的行为

|验收项|必要证据|
|---|---|
|真实四接口|CPU 入口确实实例化现有 Components/Runtime；一段实际传感器闭环具有跨四模块调用来源链。缺少任一实际后端时明确标降级，不能仍报告完整四模块能力|
|坐标与传感器|非零地图原点、非方形窗口、四朝向的坐标往返和 RGB-D 反投影例子；传感器时间错配／无深度／无位姿按固定规则处理。ROS1 适配采用相同 SensorPacket，ZED 位姿源和相机／激光外参有记录|
|每帧只融合一次|重复包不会再次增加 TSDF、语义支持、奖励或动作成本；跨场景与跨回合状态互不污染|
|真实语义贡献|同一实际历史和同一公共候选上重算 G/O/S/X/M，非语义输入哈希一致；类别交换只影响条件项，缺失精确回退；至少能观察到合法的类别条件决策变化。之后整轨迹效果仍需独立冻结实验，不能以这项单步因果接线代替|
|目标朝向及层次|全局节点选择可追到局部观察目标；在同一位置但错误朝向不能提前完成；拓扑目标落窗通过已知连通路径，不能直接裁剪穿墙|
|剩余预算再规划|至少一个真实选项结束后仍有预算的案例产生第二次全局选择和实际运动；每次使用实时 $b_t$。另有无可用收益／预算不足时返程的案例；不依赖免费静止帧凑时长|
|RPN 实际保护|最新地图让下一足迹不安全、使当前足迹不安全、返程断连、朝向恢复导致预算不足等案例均正确拒绝／停止；此项验证确定性门禁，不验证概率校准|
|IGCR 实际反馈|相同当前几何和同一候选、仅改变被消费的已执行观察账本时，响应去重／选项完成状态按合同变化；正常闭环中下一决策引用实际反馈版本。若冻结反馈对行为没有影响，报告该模块尚无可验证贡献|
|终止与重置|末动作对应的真实传感器和奖励只入账一次且先于 reset；下一回合首帧不污染上回合；停止无额外 step；失败终点、未达目标和未回锚点均保留|
|独立回放|记录下来的真实闭环逐动作重放，重建、支付、反馈、选择版本、目标状态及终止一致。回放不得读取未来评价指标来修复早期决策|

这些测试应针对会改变运行结论的故障和状态转换，不为每个 getter 写镜像测试。CPU 首轮使用单进程、单线程数值后端和明确资源记录；运行时延、地图重建时延与传感器时间都报告，不能仅凭动作数推断实时性。

## 7. 合理消融与归因边界

消融分为“同一历史上的接口因果检查”和“从相同初始条件独立实际执行的完整闭环比较”。后者轨迹分叉后各自收到自己的真实观测，不能把完整 S 的未来帧送给 G，或复用一条路线的终点作为另一条路线的结果。所有模式共用传感器、重建后端、预算、地图安全门和评价支持集。

|消融|改变什么|保持什么／要回答的问题|
|---|---|---|
|S→O/G|去掉细类别条件先验，保留实际对象支持或共同几何支持|候选、共同项、成本与安全相同；细类别是否贡献超过对象性和几何|
|X/M|实际交换／缺失类别解释|物理传感器和非语义地图不变；缺失回退是否精确，错误类别是否影响决策|
|无 IGCR 历史反馈|仍接收新传感器和更新地图，但冻结专属“已执行观察支持／进展”账本，不冻结基础地图或预算安全计数|隔离额外反馈去重的贡献；所有实际结果仍由独立评估器照常统计。该故意消融只能用于仿真，不能删除安全相关返程信息|
|单次全局计划|初次选项完成后按预定停止／返程策略结束，末值保持用于同预算诊断|区别真实剩余预算重规划的收益；不能因此把未花预算算成额外面积效率优势|
|无全局拓扑关系|同一局部观测候选由预先固定的平面选择规则决策，仍保持真实局部执行|区分全局节点／路径组织的贡献；单房间无拓扑差异时如实报告无法验证该优势|
|无学习 UQ|移除学习概率／方差调制，保留共同硬安全门|只有存在实际兼容且完成校准的 UQ 后端时才有意义。首轮仅有确定性门禁时不能将“无模型”当成有效 UQ 消融|

“关闭全部安全保护”不能用作提高任务表现的合理主对照。旧四模块全部调用并不要求每个模块都在所有场景产生正增益，但任何写入论文的独立模块贡献都需对应可验证消融；无差异或负贡献不能隐藏。

## 8. 完成定义与后续实验边界

V10 接线合同完成，需要上述传感器／状态／调用链真实实现，末帧反馈和剩余预算闭环能运行，重要状态转换测试通过，且至少一段完整 CPU 轨迹独立回放通过。只通过模拟对象或函数调用计数不算完成；只在独立 competition 脚本运行也不算四接口接入。

这仍不等于论文整体目标达成。完整覆盖规划的优势域还需另行冻结从未知或部分未知地图出发的完整任务，统一报告二维覆盖、全场重建精确率／召回率／F1、$C\times F1$、真实全程 AUC、成本和失败，并运行同后端的可执行主流基线。若首轮全局策略是 CPU 替代提议、语义是标记先验或位姿是仿真真值，分别标明其证据边界。

本合同不新增基于 V9.1 部分结果的效应阈值、权重或场景挑选。V10 的算法细节、数据角色、消融及效果门槛应在实现可审查后、任何新未来收益之前另行封存。ANS 双层和四模块接口继续保留，学习响应、自然语义、概率校准、真实位姿及 ROS1 实车闭环仍需各自证据。
