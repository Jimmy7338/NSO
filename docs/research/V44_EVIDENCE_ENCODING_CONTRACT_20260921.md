# V44 完整步骤日志无损编码

日期：2026-09-21。文件 `nso/evidence_writer_v44.py` 和 `scripts/run_development_v44.py`。

V43 固定解析接线保存的完整候选、结构分量与决策记录较大。每例仍限定 64 MiB，如果逐步保存未压缩 JSON，长轨迹或多实例可能在动作预算之前耗尽产物额度。V44 只改变存储编码，不删除候选、截断字段或改变规划策略。

## 编码与资源合同

- `steps/NNN.json` 写入为 `steps/NNN.json.gz`，采用 V43 规范 JSON、gzip level 6、mtime=0。
- 原始 JSON 文档仍不能超过 32 MiB；实际压缩字节计入原 64 MiB 每例总额。原文上限不因压缩率提高而放宽。
- `started.json`、`result.json`、执行收据、源码、传感包和完整预测格式保持原样。最终额外保存 `encoding.json`，记录每步原始字节和保存字节。
- manifest 对真实保存的压缩文件计算 SHA256。解码器验证哈希并有界解压，拒绝同一步同时出现普通 JSON 与 gzip 两个版本。
- 每步记录不能使用 256 KiB 终止预留；重复文件不能覆盖。压缩不保证未来任意轨迹必定小于总额，超额仍保留失败并停止。

新的入口继续读取冻结的 V43 运行协议，使用同一个持久五槽账本与默认输出根目录。更换入口不会重置启动次数，也没有增加重放槽位。依旧先检查 `max(10 GiB, 2×预计批峰值+2 GiB)`，通过后才加载资产、预约或创建实际场景。旧 V43 源码、协议与证据保持不变。

独立复核发现旧入口在异常处理时，若再次关闭传感器也抛异常，可能中断失败记账。新 V44 入口将二次关闭异常单列为 `sensor_close_error`，保留最初错误并继续写失败记录。持久存储本身不可写或进程被杀时仍可能留下未完成预约，不能宣称所有系统级故障都可恢复。

## 验证范围

验证包括：无损字节还原、相同输入的确定性编码、压缩文件哈希、原文长度限制、终止预留、重复与别名拒绝。另将四份既有 V43 决策 JSON 规范化并压缩，逐字节解码比对。压缩率仅代表这些保存的解析样本，不能当作未来批次峰值保证，也不增加场景数或语义性能样本数。
