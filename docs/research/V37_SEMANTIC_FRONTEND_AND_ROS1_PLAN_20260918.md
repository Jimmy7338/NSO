# V37 下一步：核验真实类别先验与实车数据接口

2026-09-18。本计划在V36采集期间准备，现已确认V36终态和独立门均通过。主任务累计35/36，不再追加当前场景族、噪声或预算扫描；未使用的1条不是自动补跑额度。以下工作优先补自然类别知识与数据接口，当前尚未执行。

## 先补哪一项证据

V35/V36检验的是“可读类别对观察侧有知识价值”这一受控机制：type_A/type_B通过人工RGB标记获得，类别到观察侧的对应已作为公共任务先验给定。这个先验不能直接等同于自然物体类别或已训练开放词汇网络。因此下一步首先确认真实设备中是否存在可学习、可迁移的类别—观察侧／外露结构关联，以及RGB前端能否可靠提供这一类别。不要继续把颜色分类的成功写成语义感知创新。

先做一份有来源的资产与类别表：设备类别的实际含义、可从正面识别的外观或铭牌信息、可观测外部结构、CAD或说明资料来源、任务价值，以及这个关联不成立的反例。若只能依据设备型号铭牌匹配目录，明确称“设备身份／目录语义先验”；若依赖人工二维码，明确称可读标签条件建档。不能在没有相应数据时写成普通自然类别泛化。

## 有界前端验证

1. 盘点本地可用的自然设备图像、原始ROS bag、已存在模型与CPU运行依赖，先出真实可用清单；不默认下载大模型、完整数据集或ROS镜像。若缺少合法任务图像，明确提出回校需要采集的类别和视点，不用渲染颜色图片填充自然验证集。
2. 在看下游成绩前固定类别定义和数据分组。小规模可行性试验目标为至少两类、每类五个独立设备实例、每实例两个不同视点；按设备实例隔离校准与留出，近邻帧不当独立样本。达不到该规模则报告实际规模，不虚称统计充分。
3. 固定一个与已有CPU资产兼容的类别前端，记录输入图像、输出类别概率、未知／拒识、实例关联与来源帧。类型名称、文件名、目录、GT构型不得作为推理捷径。先报告混淆矩阵、类别覆盖与拒识率、CPU时延及先验关系命中情况；不只报告能识别的有利样本。
4. 接入四模块时保留G相同的通用几何补看、模板和返航能力，语义只改变类别条件先验。低置信与未知回退共同先验，重复帧不能累加成虚假确信。先用保存记录做接口检查；未执行的新动作不得赋予假造终点质量。

以上仅新增数据／接口审计，不自动授权新的虚拟物理矩阵或重置36条限额。若要把真实前端放入完整闭环，应在前端可行后另行冻结小批量协议、基准、失败条件和额度，不能把同一开发集反复调参称独立确认。

## 回校前应交付的ROS1材料

复用已有`record_ros1_rgbd_v3.py`、来源元数据与离线检查器，不重复实现。已知小车为ROS1、ZED深度和位姿、镭神单线雷达及IMU/GPS；具体话题、外参、光学坐标系和驱动语义仍按实机核验。

准备一份录制清单，覆盖RGB、配准深度、CameraInfo、LaserScan、相机／机器人位姿、IMU/GPS、`/tf`和`/tf_static`，同时保存原始bag与V3原始数值记录。先离线核对时间同步、深度单位、无效雷达值、ROI/binning内参和实际TF，再检查同一静态物体多视图对齐。当前精确模拟位姿的结论不能用来证明ZED位姿或外参正确。

现有真实ROS通信夹具尚未运行；此前模拟回调测试只能证明代码合同。资源允许时在已配置ROS1的环境运行一次已存在的合成通信夹具，再用实机静态录包验收；这一阶段不发布运动命令。在线小车闭环还需要连续可达图、局部控制与安全返航适配，不能把V35/V36的已知整数安全图直接当实车导航。
