# V40 P1：六个开发场景的静态几何资产

本阶段将 P0 的六个 DEV 配置转换为可解析三角网格，不修改 P0 文件、scene contract 或测试 seed。这里只实现开发资产，不实例化 World，不生成传感帧/探索轨迹，不评价 S/G 或筛选有利结果。下面的场景结构为执行前固定设计。

## 1. 最小开发场景

|族|场地尺寸|设施数|结构设置与用途|
|---|---|---:|---|
|A 机柜/机房|10×8 m|4|凹腔、百叶与平面柜体；中间短遮挡墙，检查不同方向的观测机会。|
|B 货架|12×8 m|4|货架框架、凹腔、百叶；较宽设施与中央遮挡块。|
|C 混合设施|10×9 m|4|四类结构、异质类别和包含斜向的位姿，形成不同局部观察条件。|
|D 几何中性|10×8 m|4|相同平面实体、不同类别，没有中央遮挡；不预设语义一定有收益。|
|E 覆盖压力|20×14 m|4|相同量级设施分散放置，中间长遮挡墙两端可绕行；只扩大尺度，不放宽重建阈值。|
|F 先验失配|10×8 m|4|预先选取类别条件表中低概率结构；类别标记仍正确，不把关系偏移与识别错误混为同一因素。|

类别、结构、尺寸与位姿是独立字段，类别不是隐藏构型的编码。四个类别和四种抽象结构在 24 个开发设施中呈多对多关系。设施尺寸和小幅平移只使用对应已有 DEV seed；D 保持规则几何。不读取测试 escrow、未来测试配置、实际 S/G 路线或质量分数。

这是任务相关的最小开发套件，尚不足以证明跨场景泛化。正式父场景及其网格仍未生成；旋转和结构变体不增加独立样本数。P0 先验仍是未校准的开发设计表，这一步不声称训练完成。

## 2. 网格与标记

`nso/development_geometry_v40.py` 提供：

```python
build_development_geometry(scene_spec, protocol) -> DevelopmentGeometryV40
union_box_mesh(boxes) -> (vertices, triangles)
structure_boxes(structure, dimensions) -> (local_solid_boxes, marker_plane)
mesh_audit(vertices, triangles, triangle_instance_id) -> dict
load_mesh_arrays(path) -> dict
```

核心数组为 `vertices: float64[N,3]`、`triangles: int32[M,3]`、`triangle_instance_id: int32[M]`，背景 ID 为 -1，设施 ID 为 0—3；另有 `triangle_rgb: uint8[M,3]`，只含中性材质色，不把类别涂到整件设施。数组兼容现有 Open3D TriangleMesh 的 vertices/triangles 输入，解析器本身不初始化 Open3D 或 World。

每设施由有厚度实体盒的并集生成边界。坐标分割后只输出占据/空闲边界，移除并集内部面，共享分割网格顶点以避免 T-junction。等价算术坐标按 12 位小数合并，避免浮点薄片。凹腔、百叶间隙和货架开口是真实材料之间的空间，材料边界本身闭合；它们不是缺失三角面。

四种结构均有同样的小型实体标牌，类别仅控制其面内 .32×.30 m 区域的人工 RGB 标记。`marker_patches` 给出实际标记中心、法向、面内坐标轴、尺寸和颜色，属于 renderer 私有信息；后续渲染器只能对实际第一命中点位于该实体面片内的像素赋色。标记不暴露整实例分割、结构或仿真 owner ID，不代表自然语义网络。

设施与背景分别闭合且不相交于体积。设施底面与地面接触，因此两套独立封闭表面中存在不可见接触面；后续评价必须按预声明候选与传感范围建立可观察集合，不能直接把所有三角面当成任务目标。此步骤没有完成该集合的冻结。

## 3. 私有资产与公开任务元数据

每父输出：

- `renderer_private/geometry.npz`：上述四个数组，供传感/独立评价读取，规划器禁止读取。
- `renderer_private/markers.json`：物理标记面片，供第一命中 RGB 赋色。
- `evaluation_private/instances.json`：固定含 `private_instances / background_boxes / public_workspace` 三字段，并明确实际几何为 GT、可观察目标集合仍 pending。
- `evaluation_private/mesh_audit.json`：有限数、面积、闭合边、正向体积等静态校验，不能当作重建质量分数。
- `public_workspace.json`：声明场地外边界、墙内边界、起点 `[.75,.75,.9]`、初始 yaw=0 和所有方法共用类别调色板。没有实例列表/ROI/构型；公共导航图仍 pending。
- `public_planner_spec.json`：从旧 DEV spec 以旧协议严格提取的原样公开输入，不加入新键，不改变其 pending 状态。

`private_instances` 每项包含真实类别、结构、尺寸、`position_world_m`（底面局部原点）、`center_world_m`、yaw、旋转矩阵、局部实体盒和世界 AABB。`conservative_footprint_xy_m` 为世界 AABB 的四角，供独立几何可达性/碰撞审核；这是实际实例真值，不是规划器免费地图。

`background_boxes` 采用 `[xmin,xmax,ymin,ymax,zmin,zmax]`。计算二维障碍时须排除 `zmax<=0` 的地面盒。主线可用这些私有几何、半径膨胀和 BFS 形成独立评价的预定义可达视点，并按相机朝向检查可见性；这些视点不能传给 planner 或称作已实现的公共导航图。

## 4. 构建、校验与资源边界

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -p test_development_geometry_v40_p1.py -v
PYTHONDONTWRITEBYTECODE=1 python3 scripts/build_development_geometry_v40.py
```

默认输出为 `audit_results/v40_p1_development_geometry_20260920/`，仅此新目录；已有目录拒绝覆盖。所有计划 payload 在写盘前核对 **16 MiB** 总量上限。manifest 记录源文件及既有 DEV spec SHA、每项输出 SHA、逻辑数组 SHA，并把 World、帧、策略轨迹、质量评价计数明确保持为 0。测试使用临时目录；正式资产由主线调用构建器一次生成。

静态测试覆盖实体并集内部面删除、局部法向朝外、真实凹腔、标牌接触、六族闭合表面、类别/结构多对多、确定性、拒绝测试 split、背景/设施分离、保守膨胀后的静态连通邻域、NPZ 解析和非法索引、私有字段不进入公开输入。BFS 只是开发场景可行性检查，不输出导航图，不使用规划收益。

后续仍需独立完成：CPU 第一命中传感接口、付费动作账本、实际实例关联、公共导航来源、预定义可观察外表面评价、从动作 0 自主运行及质量/运行时比较。看到完整 GT 开发场景图不能写成机器人已重建场景或系统优势结果。
