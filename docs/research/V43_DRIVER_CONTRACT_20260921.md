# V43 开发运行器、记账与物理启动门

日期：2026-09-21。实现：`nso/episode_driver_v43.py`、`nso/diagnostic_policy_v43.py`、`scripts/run_development_v43.py`。运行协议：`configs/virtual3d/v43_runtime_protocol_20260921.json`。本文件描述已实现接口；本轮没有实际 DEV World 或完整自主轨迹。

## 启动顺序和资源

入口仅接受五个预声明开发槽位，且持久存储检查先于导航资产加载、输出目录创建、启动账本预约、mapper 创建和 World 创建。要求沿用 `max(10 GiB, 2×预计批峰值+2 GiB)`；当前声明批峰值 384 MiB，最低要求仍为 10 GiB。没有绕过参数，也不接受 RAM 作为持久结果目录。

当前环境可用以下入口只做准备检查：

```bash
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 \
PYTHONDONTWRITEBYTECODE=1 .venv-3d/bin/python -B \
scripts/run_development_v43.py --run-id R2_A_diagnostic --preflight-only
```

资源不足返回 `blocked_before_world_creation`，退出码为 2，不预约启动槽位。空间满足时，`--preflight-only` 验证公开 bundle、控制器构造和 Open3D 依赖，仍不创建 World。去掉该标志才会在所有门通过后运行对应开发槽位。这里不是对当前机器已能开始实际仿真的声明。

已声明的槽位是 R2_A_diagnostic、R3_A_G、R3_A_S、R4_C_G、R4_C_S，分别绑定 DEV_A/DEV_C、方法和固定开发噪声种子。全批最多五次预约，无自动重试。预约账本位于仓库固定路径 `audit_results/v43_development_batch_20260921/start_ledger.json`，更换输出目录不能刷新槽位。留出集资产与种子不进入该入口。

R2 固定诊断为 **14 个付费原语**：前进 0.25 m、左转六次、前进 0.25 m、左转六次，完整回到起始 XY 和朝向。旧建议中的“约 12 动作”不足以完成这项完整往返，现明确冻结为 14。该固定序列不是自主规划。DEV_A 当前含四个设施，所以 R3 明确是 DEV_A 首次自主接线，不冒称单设施研究。独立策略重放尚未接入，本入口不消耗或授予重放额度。

## 每帧的实际时序

1. 初始步骤取得唯一传感 grant；其后只执行上一步已提交的一个原语。
2. 先持久保存原始 RGB-D、scan 与执行 receipt，包括随后被判定为不合法的已取得包。
3. 在融合前核对动作、步号、成本、碰撞、上一位姿、0.25 m／30°运动、0.9 m 相机高度、0.3 m 扫描高度及扫描位置和朝向。V41 仿真明确以 paid step 为扫描时间戳，运行器检查此关系；通用 V42 mapper 不作该假设。
4. mapper 只融合一次，再由控制器接收当前帧，完成实例与残差、视角缓存、安全图更新。
5. 当前证据更新结束后才选择下一动作，保存全模块收据与候选摘要。`left/right` 明确转换为传感器的 `turn_left/turn_right`。

付费碰撞尝试不产生位移，但仍占一次动作及一次观测。运行器分别记录已提交动作、成功取得并核验的执行记录、已保存包、mapper 帧数和 TSDF 融合次数。动作提交后采集异常不能伪装成从未尝试，也不会自动再执行。

## 保存、终止和恢复边界

每例上限 64 MiB，单文件上限 32 MiB，实际入口保留 256 KiB 用于终止记录与摘要清单；这部分包含在总上限内。文件以排他创建写入，不能覆盖旧尝试；关键数据和启动账本同步到磁盘。启动使用独立文件锁，失败预约仍保留。同一个 run ID 不能重新预约，第六个启动被拒绝。

终止区分正常控制器停止、无法继续或返航、预算耗尽、时间限制、输出上限、执行错误和预测保存失败。只有 sensor 明确确认起始 XY/yaw 才把控制器 `stop` 留作普通停止，否则记为 `stopped_without_confirmed_return`。停止不代表覆盖或质量达标；本入口不计算任何 GT 质量分数。

运行器最多 160 个付费动作，默认 600 s 回合时间限制在步骤边界检查。各阶段耗时单列；它**不是可中断所有 C++ 后端调用的硬实时看门狗**。控制器有候选、实例和无进展次数上限，但尚未验证大图规划耗时，也未实现原建议的硬 2 s 每次规划中断。长时调用需在实际开发资源检查中测量，不能先宣称实时性。

完整预测只在终止阶段提取，不因保存 checkpoint 再融合帧；原型和真值不会补入网格。预测网格、占据图、实际包、动作、错误、源码快照和 SHA 清单封存后，才允许独立离线评价。当前评分和重放驱动仍待接入；代码包含保存入口不等于已经完成实际运行验证。

Open3D 后端不能事务回滚。融合失败时 mapper 标记不可继续，控制器的部分更新异常也会终止回合；不能简单重传同一帧声称恢复成功。若进程在预约后崩溃，未完成预约保留，需要另行审计，不会自动释放额度。

## 本轮测试的真实范围

13 项运行器测试使用有限且事先指定的传感包、调用顺序记录器和少量实际解析 TSDF 接线；没有临时构造可供策略自由探索的仿真环境。测试验证逐帧顺序、错误包保留、扫描／位姿配对、碰撞收费、失败动作记账、返航确认、输出保留额度、不可覆盖路径及启动槽位上限。真实入口在当前磁盘条件下的拒绝路径也被直接验证，未调用 World 工厂。

R2 诊断策略的序列在公共图上静态核验可返回，首帧可接实际解析 mapper；14 个动作尚未在 DEV 传感器上执行。完整 ANS 控制器测试与运行器有限替身测试分别报告，不把两者拼成已经完成的完整自主实验。
