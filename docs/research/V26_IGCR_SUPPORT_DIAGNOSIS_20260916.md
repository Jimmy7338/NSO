## 2. 哪一层拒绝了更新

冻结 `nso/observed_runtime_v26.py:61` 在每个已授权、身份／动作／位姿／时序核验后的付费观测到达时，先更新 mapper，再构造新的几何状态。无碰撞时把**相邻两帧状态**和观测前已知的 cues 交给 `observe_transition`。

`nso/observed_planner_v26.py:340` 的更新链为：

1. 必须为连续、未重复计数的一个付费转换。
2. 必须抵达当前选中端点，位置和朝向均相同；路途中不更新方向反馈表。
3. 对应 cue 在上一帧前已知，选中选项保存的预测收益为正，当前基于观测障碍和相机视场的模板仍可见。
4. 机器人到 cue 的水平距离在 0.5–2.5 m，当前方向扇区与选项的预测扇区一致。
5. 在两帧采样集合中 key 都存在、且当前点到 cue 水平距离不超过 1.5 m 的面片至少 4 个。
6. 通过后才把共同 key 的新增方向位／最近距离减少超过 1 cm，计成 `min(1, improved/16)` 支持代理并更新反馈表。新增采样 key 不计作新增重建面。

13 条明确 `unavailable` 表明它们已经通过前面适用性条件，实际阻断点就是第 5 步。门槛失败按“不可用”保留，未伪造成零收益，这是正确的缺失数据区分；但也意味着这批结果不能验证预期的 IGCR 纠偏作用。

## 3. 证据支持什么根因，尚不能确定什么

**已确认存在严重跨帧换样。** `nso/observed_state_v26.py:198–215` 将全地图符合几何要求的 quality 面片按 key 排序，每帧对整个列表重新 `linspace` 截取最多 256 个。排序是确定的，但列表增长或成员变化时，选中的具体 key 不固定。S 的 104 次规划快照中，初帧为 157 个，后续 103 次均为 256 个。400 次转换的 `sampled_key_entries` 中位数为 **242**、最大 **254**；319 次至少 192 个、270 次至少 230 个当前采样 key 在上一帧采样中不存在。G 中位数也达 240，说明问题并非只有 S 的类别输入才出现。

这些数是“采样集合的新增成员”，不是新表面面积。它们直接证实共同 key 追踪承受了强烈的集合变化。结合 13 次局部共同数仅 0/1，**全局截断采样及其换样，是反馈失去局部共同支持的有证据嫌疑因素**。但日志没有保存两帧完整的未抽样 quality 字典，也没有保存完整局部面片数，所以不能分离：局部原本稀疏、远处新增几何挤动抽样索引、噪声造成新体素、或这些因素共同作用；不能声称已证明“原始实测支持充分，只是采样丢光了”。

**已确认窗口只取抵达前的最后一步。** 反馈没有比较选项开始到终点的完整付费观测过程。S 全部转换记录了 226 个“共同 key 改善事件”（可跨动作重复，不是独立表面计数），其中 225 个发生在非端点转换，端点转换仅 1 个；该 1 个位于动作 344，局部共同数仍为 0，因而不是目标 cue 的可用收益。这说明大量全局支持变化发生在当前方向反馈排除的时段，但不能据此认定其中多少属于目标设施，更不能把它们代换成 Q 增益。

**当前不能给出两因素的因果占比。** 改抽样是否足够、扩展窗口是否足够、保持同一轨迹能否产生有效方向更新，均未经此次只读核查验证。不能从本诊断预言修复后 S 将超过 G，也不能把第一对结论外推至第二个类别排列。

## 4. 一项有限的后续修复建议（未实施）

下一版本只增加一个“**固定 key 的付费选项观测账本**”：选项建立时，从实际 mapper 的几何字段按类别无关规则固定局部支持 key，分别保留起始 n／bits／range；随后逐付费帧更新这些 key 的真实支持，到达或取消时按明确的归因窗口结算。账本与规划用的 256 个全局样本分离，不让远处新 key 改变已登记面片身份。局部范围只能来自已观测选项／cue 位置，禁止 owner、隐藏尺寸、参考窗、GT Q、未来帧或未观测附件；G/S 对同一几何选项使用相同的支持提取规则。

先验证“无关远处新面片不清空共同支持”“补看路途中发生的已知 key 改善不会因末步为转弯而消失”“实际支持不足仍是 unavailable，重复动作不重计”。保持现有至少 4 个支持的要求，不直接降低门槛或把缺失值换成乐观收益。新出现 key 仍单列审计，不当作重建改善。该账本只修复可比较证据和时序归因，仍是观测支持代理，不是终点外形 Q 的监督标签。

是否进入保存数据上的新版本机制检查，需另行冻结并授权；**本批四主任务／四回放原算法、场景和指标均不变**。
