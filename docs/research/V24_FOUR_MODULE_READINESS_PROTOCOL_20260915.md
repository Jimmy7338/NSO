# V24 实际共同前缀接入四模块的就绪检查

日期：2026-09-15。此检查在四条前缀采集及四次不同进程验证全部完成后，另由主任务授权执行；脚本不等待数据、不调度传感器、不自动启动实验。

输入仅为保存的完整 SensorPacket 序列、公共 world_config/shape、公开双设施数量2、实际末包位置及朝向2的返航锚点。P00/P01的234/254次前缀动作全部计费；总预算387/421只是本次静态建议诊断，余量分别153/167，尚不是正式任务主预算。模拟器、真实物体、服务区域、静态规划路线、隐藏尺寸及评价结果不传入候选生成。旧路径文件只能作为已采集证据存在于清单，不读取其路线来造候选。

每条保存前缀分别重建一次N和G，共8次 `start_sensor_episode`，全部实际0—234或0—254包按顺序输入。每个状态只调用一次 `choose_goal`；另调用一次公开 `plan_observed_return` 留下RPN-UQ实际返航检查记录。禁止 `next_local_action`、付费动作授权、`world.step/sense/scan` 或执行任何候选。保存四模块真实调用日志以及全部拒绝/异常，不把安全候选视作已经到达的设施或成功完成任务。

运行时采用冻结的 `FacilityRuntimeV21/facility_components_v21`，task_asset_count固定2。OV-SDF仍是实测人工标记与几何分组；STGHP为公共N/G候选，RPN-UQ为当前观测地图的确定性守卫，IGCR为前缀记账及规划反馈。未部署学习的语义排序或不确定性网络；本脚本也未把V24外形清理/补全后端接入V21评分。因此四接口被调用不等于完整学习架构效能已验证。

`ObservedRuntimeMapperV10`继承`QualityMapperV2`更新链，额外记录camera_seen、关键帧及机器人自身格的已观测障碍冲突。按实际保存数据核对TSDF三数组、去类别的surface/quality，以及belief/visible摘要；不先假定belief完全相同。差异与自身格冲突计数必须保留。实际两个标记若被几何分组丢失或合并，也作为未就绪记录。

按当前实现，付费总账会扣除整个前缀，但V21覆盖预算账本仅在末包初始化，不重建前缀覆盖意图的历史速率。报告C_ROI、缺口、保守速率和每候选预算门；禁止注入猜测速率或偷偷放宽预算。区分所有预算放行、正质量项、非coverage角色及真正选中候选；没有后续动作，因此实际quality动作、目标到达和终点质量均不可用。

检查同一记录的N/G公共候选池、资产几何与覆盖分数一致；同父类别交换时检查相同的非语义前缀、几何候选、分数与选择。类别票数可记录为观测诊断，但不进入N/G排序。逐条候选只验证当前已知安全地图上的动作/状态、转弯费用及返航锚点；未知地图及未来观测不会被当成通行或收益证明。

按两个实际观测标记对应的asset_index分别报告非coverage角色，以及预算放行且质量项为正的角色，不能把任意一个候选存在解释为两个设施均有可选臂。该关联只是候选角色声明，不证明后续目标已被看到。每次写JSON或压缩日志前保留至少32MiB；创建本次输出后发生的外层异常记录失败回执并退出非零，已完成案例保留。若空间边界使失败回执本身无法保存，则明确打印真实异常到终端，不覆盖旧输出或清理原始包。

执行前后核验完整根/案例清单、原始包与网格、源码及独立前缀验证。结果写入新 `audit_results/facility_runtime_v24_readiness_20260915`，所有失败保留。只有问题暴露和候选可用性属于本检查结论；下一步是否需要新版本候选、预算或语义信息设计由主任务根据完整诊断决定，不能直接跳到大矩阵或宣称语义胜出。
