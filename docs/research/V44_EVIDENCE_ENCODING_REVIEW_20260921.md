## 结果

- 四项编码测试通过：确定性与无损字节、压缩哈希、原文长度上限、总产物额度与终止预留、重复文件和别名拒绝。
- 四份固定 V43 回执先按真实 writer 的 `canonical_bytes` 规范化，再压缩。原文共 **1,327,099 B**，gzip 共 **208,637 B**，减少 **84.28%**，四份逐字节解压一致。没有用 pretty JSON 大小充当实际运行原文大小。
- 所有压缩前原文仍受 32 MiB 单文件上限约束；压缩后字节计入原 64 MiB 每例总额，步骤记录不能使用 256 KiB 终止预留。
- 入口继续读取同一 V43 协议和持久五槽账本，空间检查仍先于资产读取、预约和 World 创建。

复核发现外层异常处理直接再次调用 `sensor.close()`，若该调用也失败，原始失败记录和预约完成状态可能无法保存。新 V44 入口已经修正：二次异常保存至 `sensor_close_error`，继续记录最初错误。对最终入口的这一异常处理代码段进行了有限对象验证：强制主错误与二次关闭错误，确认两者均保存，账本完成调用绑定实际失败文件 SHA256。验证仅提取异常处理代码，不调用入口、资源 gate、场景资产或 World。
