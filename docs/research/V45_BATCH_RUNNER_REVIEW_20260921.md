## 发现的问题与复验

初版 `bounded_subprocess_v45` 只在存在未关闭管道时循环。子进程关闭 stdout/stderr 后仍运行，会越过统一截止，进入固定的 `wait(timeout=5)`。独立有限复现使用标准 Python：先向 stdout 写入 `prefix\n`，关闭文件描述符 1、2，再休眠 0.5 秒；声明超时为 0.05 秒。初版返回 `status=exited`、退出码 0、耗时约 0.5266 秒，而没有触发硬截止。若子进程继续超过 5 秒，异常还会使上层来不及写入完整命令回执。

修正将循环条件改为“仍有管道或进程尚未退出”，在两种状态下使用同一截止。超时终止进程组，保留已捕获的有界日志。启动失败、I/O 异常和无法确认退出也形成明确状态，不自动重试。独立再次执行同一有限命令，得到 `status=hard_timeout`、退出码 −9、`stdout=prefix\n`、`process_exit_confirmed=true`，耗时约 0.1125 秒。该耗时包括轮询和终止回收，不是实时规划性能。

实现者补入关闭双管道正常结束、关闭双管道超时、启动失败的测试。编排器配套测试共 26 项。根代理最终集成验证包含编排器与报告器共 41 项，`audit_results/v45_batch_validation_r1_20260921/test_result.json` 记录退出码 0，`unittest.txt` 记录 41 项全部通过；审查者读取这两份实际保存收据确认。本审查另独立复验上述缺陷，不重复整套集成验证。

## 合同检查

| 检查项 | 审查结果 |
|---|---|
| 实际运行资源门 | 对用户选定 episode 输出先执行冻结的 10 GiB 持久存储门；失败时不读取参考、不建输出、不写 journal、不预留 World、不调用子进程。每个新槽以及原 V44/传感器工厂继续检查资源。 |
| 仓库启动日志资源 | journal 只写有界元数据，要求持久文件系统与 64 MiB。它没有替换实际 episode 的 10 GiB 门，允许外部持久盘承担实验数据。 |
| 启动次数与恢复 | 顺序严格固定为 R2、A/G、A/S、C/G、C/S；原 V43 五槽 ledger 不清空。启动前写永久 launch，进程在 reserve 前中断也不能通过换输出目录重启。 |
| 进程互斥 | 仓库 journal 的非阻塞进程锁避免两个编排器并发启动同一槽；真正的 World 预留仍由原 V44/V43 ledger 完成。 |
| 失败保留 | 文件独占创建，失败、孤立目录、缺少完整回执的后处理不会被覆盖或自动重试。账本损坏时保留错误总结，将无法确认的计数字段设为 null。 |
| 未知 World 数 | 有 launch、无 reservation 时标记 `world_created=null`，保留在 `launches_without_reservation`，不把“未确认”报为零。 |
| G/S 公平性 | 继承同一冻结控制器参数、公共候选导航和槽协议；G 的正常任务未成功不会因低表现取消 S。技术错误或评价无法绑定来源则停止并保留未执行槽。 |
| 先诊断后自主 | R2 必须确认返航且完整保存观测重算通过，才能启动自主槽；不以 R2 的三维分数高低选择是否继续。 |
| 重算与评价隔离 | 完成预测的 episode manifest、预封存参考及源码先绑定；重算只使用已保存观测，不是新 World 重放。评价不改变策略或选择参考。 |
| 恢复绑定 | 已有命令回执的标准流及评价结果按 SHA 核验；重算派生 JSON 还验证规范字节内容。重用后处理不新增 World；部分后处理不静默重跑。 |
| 输出上限 | stdout/stderr 各保留至多 256 KiB，超限标记失败并终止进程组；编排元数据 32 MiB、独立 episode 64 MiB 的上限继承各自实现。 |

保存观测重算器还核验当前源码与 episode 归档源码、原始 ledger、全部预测清单和终点状态。因此不能仅凭新生成的 summary，把来源不一致的旧 episode 当作当前配对实验。

## 适用边界

900 秒是外层故障终止门，原 V43 的 600 秒限制仍在步骤边界检查。此审查没有证明单次规划满足 2 秒实时截止，也没有做断电、内核不可中断 I/O 或全部磁盘耗尽的实机故障注入。进程无法确认退出时仍须保留“不确定”状态；有 journal/ledger 的槽不得自动重启。

编排器自行写入的元数据使用独占写入与 fsync。继承的 V44 离线评价 CLI 对结果使用独占创建和关闭文件，没有新增显式 fsync；不能将编排器的持久化保证扩大到所有被调用程序。这个差异不影响 SHA 绑定与失败保留，但断电恢复不能仅依赖应用层成功返回。

该审查证明有限故障模型下的编排一致性，不证明 V43 新控制器已在三维环境形成完整自主闭环，也不产生语义性能增益或增加独立场景数。实际实验是否允许启动仍由所选持久输出目录的资源门决定。
