# V15 语义来源编码转换与观测特征核查

2026-09-14。新增独立模块 `nso/semantic_taxonomy_v15.py`，8 项检查通过，并在已有 60 个观测状态的 334 条候选特征上完成转换核查。**尚未接入规划器或训练模型，没有新的语义效能结论。** 正在执行的 V15 候选实验源码与配置保持冻结。

## 为什么需要显式转换

两个场景生成器使用了相反的原始编号：

| 来源协议 | 类别 2／原始投票 −1 | 类别 3／原始投票 +1 |
|---|---|---|
| `competition_v9`，Q 系列 | 开放货架 | 封闭设备柜 |
| `inspection_v4`，D12 系列 | 封闭设备 | 开放复杂结构 |

旧固定先验中的 `1-vote` 以 Q 的类别含义解释投票；直接应用到 D12 会反转该先验的类别意义。当前 V15 只使用 G 几何策略，不因这个问题改变已有实验结论。该发现也不能用于解释全部历史负结果：Q 内部的 V13/V13.2 信息门槛失败仍是原范围内的有效负证据。

统一编码使用“开放结构为 −1、封闭设备为 +1”：Q 投票保持，D12 投票取反。零投票仍为零，混合概率对应的连续投票做线性变换。来源协议必须明确提供；未知协议或重复编码会被拒绝，不根据世界名称、隐藏层板、未来回报或已知优劣猜测类别。

这里只处理这两个已有人工二类标签协议，不等于自然开放词汇分类器。D12 的反向/独立语义条件仍保留为错配条件；转换来源编号不会依据真值把错误提示重新纠正。真实外部语义源以后须提供独立的类别表和置信度契约。

## 对输入与模型容量的影响

`canonical_observed_records` 返回副本，保留原投票与来源信息用于追溯，转换后的 `class_vote` 使用统一意义；不改变实例顺序和置信度。

`canonical_feature_record` 仅转换 V14 特征的末八个类别条件矩。前 18 个公共量、整条几何特征、残差置信度、候选与实例数量保持原样，输入仍为 26 维。新增 `semantic_encoding` 是数据来源说明，**不得作为模型输入**。后续训练加载器只能选择明确列出的数值特征，不能把来源、场景、结构种子、候选标识等元数据追加进网络。

缺少证据时，语义尾部的正零/负零统一为数值零，避免相同语义因 JSON 的 `0.0` 与 `-0.0` 表示产生不同哈希；没有对非零特征取整或放宽几何配对。第一版数值核查保留于 `semantic_taxonomy_v15_20260914`，修正零的序列化后重新核查的权威结果为下述 `_1` 目录。

## 实际核查

[最终核查结果](../../audit_results/semantic_taxonomy_v15_1_20260914/result.json)：

- Q0—Q3 既有开发记录：16 个观测状态、102 条候选特征。

[8 项检查](../../audit_results/semantic_taxonomy_v15_tests_20260914/result.json)覆盖同义标签跨来源一致、混合投票、全部八个语义矩、几何/维度不变、零置信与缺证据序列化、原输入不被修改、未知协议、重复编码及无效输入。源码快照与输入/输出哈希已保存。

## 接续条件

该模块是后续学习语义与固定 S 对照的输入准备，不是已修正全部旧运行时。旧 CPU 评分后端仍直接使用其原投票；只有在新的方法版本中显式接入转换、核对实际选择调用、冻结协议并重新实验后，才能声称固定语义基线或跨来源模型已迁移。

V15 完整 46 候选实验继续按既定观测语义分组评价。它只使用 D12 单一来源，统一符号转换不会改变其组成员，也不会凭空增加可观测信息；本轮没有把转换后的特征替换进该冻结数据集。完整结果仍须按原门槛判断，单个开发父布局即使通过也不能直接晋级训练。
