## 实际做了什么

使用已有 YOLOv8n 权重，SHA256 为 `f59b3d833e2ff32e194b5bb8e08d211dc7c5bdf144b90d2c8412c47ccfc83b36`，没有新下载或训练模型。固定 Ultralytics 8.3.200、PyTorch 2.6.0+cpu、FP32、640 像素、conf=0.25、IoU=0.7、rect=false。显式设置并检查 Torch intra-op/inter-op 与 OpenCV 线程数为 1，不声称进程总共只有一个线程。

在看预测结果前固定官方安装包的 `bus.jpg`、`zidane.jpg` 两张通用例图；每图重复五次，用同一后端的官方 PIL RGB 路径各作一次输入格式对照；另有一次空白预热和一次空白负控制，共 14 次显式 `predict` 调用。后端内部预热不计入此 API 调用数。两张图不是设备验证集，重复调用不增加独立样本。

新增 `nso/cpu_semantic_detector_v37.py` 校验本地权重 SHA、固定版本和 COCO 类别空间，只接收 RGB 数组，经明确转换交给后端。已安装版本的 [官方加载代码](https://github.com/ultralytics/ultralytics/blob/v8.3.200/ultralytics/data/loaders.py)与[预处理代码](https://github.com/ultralytics/ultralytics/blob/v8.3.200/ultralytics/engine/predictor.py)表明 NumPy 输入使用 BGR；该项从此前“待核对”升级为这个固定版本上的已核实合同。原 `SemanticDetector` 和旧语义地图源码没有改写，新实现也未连接原神经 ANS 或 V35 控制器。

## 真实语义关联的结论

[设备资料审查](V37_REAL_EQUIPMENT_PRIOR_FEASIBILITY_20260920.md)给出了可反驳的候选：Keysight E36311A 与 E36312A 同属台式电源，背面输出结构不同。因此型号身份可能提供正面观测中尚不可见的结构信息；同型号的可选接口、摆放和遮挡仍有不确定性，所有设备背面也仍有普通几何观察价值。[官方手册](https://www.keysight.com/pl/en/assets/9018-04576/user-manuals/9018-04576.pdf)

这支持“设备身份／目录语义先验”作为真实任务候选，尚不支持自然大类识别、型号可读性或额外补看收益。当前 COCO 网络没有上述仪器型号标签，未取得两类×五独立设备×两视点的数据；现有左右人工类别和 5 cm 容差也不能直接用于厘米级背面端子。软件能运行、资料存在结构关联、自然识别可靠、规划重建有增益是四项不同的证据，本轮完成前两项的有界检查。
