# NSO 独立项目发布与历史材料迁移

本次按项目维护者要求清理退役实现，并以当前NSO代码、论文与实验材料建立新的主分支起点。论文引用与外部方法说明按研究实际保留，代码清理不改变论文的实验结论。

## 文件范围

删除2,945条受跟踪路径，包含旧训练入口、神经训练适配、旧模拟器及其配置、旧预训练/训练资产、数据集配置、编辑器和Python缓存，以及历史源码快照中的退役实现。`env/`和`utils/`中现用的自研CPU实现保留；类别映射继续保存在`semantic/class_mapping.py`，避免破坏语义前端接口。

131个历史源码压缩包同时包含退役实现与本项目当时的代码，因此整包退出当前发布树。剩余源码归档经检查后保留。保存的传感包、动作、信念、地图、网格、评分、失败记录与历史manifest未按结果优劣删选。

逐文件路径、旧Git对象与内容SHA256见[删除清单](standalone_cleanup_20260928/removed_files.json)；包初始化及默认依赖入口的前后摘要见[替换清单](standalone_cleanup_20260928/replaced_files.json)。这些清单只记录删除范围，不重新分发被删除的源码。

## 历史校验与当前运行

历史`source_freeze.json`、源码归档摘要及执行receipt保持原值。它们证明原实验当时绑定了哪些文件，不再代表当前发布树包含所有旧源码。尤其`env/__init__.py`已改为独立CPU包初始化，部分旧校验列表还包括已删除的模拟器文件；对当前目录直接执行旧批次的源码严格校验会失败，这是明确记录的版本迁移，不能通过篡改原摘要消除。

当前算法、环境、指标和论文构建入口保留；新采集必须用当前源码重新生成封存清单并写入独立输出，不能覆盖原批次，也不能将新包初始化冒充为原冻结源码。读取已有评分、轨迹和重建结果不需要恢复退役训练入口。要求逐字节复现历史源码闭包时，需要清理前的本地恢复版本；公开的新快照不再保证每个旧批次的完整源码归档可得。
