# 单项地面关联修正：固定付费路径核验

本轮确认了一个具体机制：**原对象支持中的近地连通区域会使已观测实例长期处于关联歧义；只在对象候选构造前排除经过当前深度核验的地面带，可以让同类实例共享在原返航开始前生效。**这项结论来自同一条已保存路径上的独立证据重建，不是新规划轨迹或三维质量提升结论。

旧 v1 的58项执行源码、场景、12条开发运行协议均未修改。新实现位于 `nso/observed_instances_article_ground_v2.py`，仅继承 ArticleV1 并替换连通分量构造前的有效像素掩码。类别支持门槛、关联歧义拒绝、缓存容量、几何反馈资格与上限、原共享模型均继承不变。完整原始 RGB-D 保持原样；本轮未创建 World、未重新渲染、未执行运动、未重新融合 TSDF，也未计算新的重建质量。

## 冻结、控制与计算环境

输入是独立复核通过的 `dev_AISLE_S_b160_n92801` 全部161帧，包括原始 frame ID 和原始观测 SHA。根代理在原运行环境执行了已预先冻结的两阶段回放。预声明位于 `audit_results/article_stage_20260928/ground_association_replay_v2_attempt03/predeclaration.json`，SHA256：

`551f23b6cc4202d5392252c8a1e15b0314de65e2c893d5ececf77cd9728f2f20`

旧前端控制首先通过：161帧，3,979,754个比较叶节点，**最大数值差0**，98个支持哈希对应完全相同，无离散字段差异。逐项比较了关联、测量残差、反馈、观测视图证据及 S 的完整结构信念；原始传感观测 SHA 完全相同。只有控制通过后，才运行新前端；新掩码、残差、反馈以及 G/B/S 信念均从付费数组重新计算，未套用旧消息。

此前两次控制失败记录完整保留。attempt01 在局部 Ubuntu `.venv` 中出现约8.9e-16 m的重投影舍入，导致支持字节哈希不同；attempt02 对完整点数组核验后，仍在第3帧多视图非线性拟合诊断量上遇到最大4.15e-7°差异。原环境与本地环境的 NumPy/SciPy 版本号相同（1.26.4/1.11.4），但 BLAS 构建不同：原 `.venv-3d` 使用 OpenBLAS64 wheel，本地使用 Ubuntu system BLAS。回到原环境后所有比较精确相同，因此没有放宽1e-12绝对数值容差，也没有忽略任何资格或动作字段。attempt01/02不是新地面前端的实验结果；两次均在旧控制阶段停止。

## 唯一修改及输入边界

固定常数先于真实新前端回放声明：相机安装高度0.9 m、轴向深度相对标准差1%、最少64个支撑像素、XY两个方向跨度各至少0.5 m、额外标定容差0.01 m、最大地面高度偏移0.03 m、最大排除带0.06 m。地面高度使用当前观测的位姿和公开安装高度建立假设，再由当前深度加权中位数、空间跨度和噪声残差核验；核验失败时整帧回退旧候选构造。

新接口仅接收严格白名单 `PaidRGBDObservationV40` 的当前 RGB-D、K、T、frame ID及付费步数。地面判断不读取颜色类别、私有资产、实例归属、设备尺寸、未来帧或评价真值。代码没有接受额外 GT 字段的接口。

10项静态测试全部通过，覆盖可测地面、支撑不足、错误高度、噪声超限、狭窄支撑、GT字段与扩展类型拒绝、原始数组不变、标记换色不改变地面掩码、设备接地边界和回退时旧前端输出完全一致。

该假设只适用于已标定安装高度、已知竖直方向、水平静态地面及当前精确位姿协议。低于约数厘米的设备接触边缘可能被排除在对象关联之外；测试明确记录了这一边界。这些像素仍保留在完整 RGB-D 中。坡道、多层地面、错误安装高度不在本轮验证范围。

## 同一路径上的主要证据

下表的时间均为原路径付费步数。第126步是**原 v1**开始返航的诊断分界，不能解释为新方案的返航时间。

| 证据事件 | 原 v1 控制 | 地面关联 v2 |
|---|---:|---:|
| 首次可靠观测平面 | 11 | 8 |
| 首次实际应用几何反馈 | 85 | 8 |
| 早期 cabinet `instance_0001` 首次反馈 | 136 | 8 |
| 首次合格且有信息的同类 peer | 136 | 82 |
| 首次 S/B 结构后验差异 | 136 | 82 |
| 原返航前存在 S/B 差异的实例×帧数 | 0 | 81 |
| 全路径关联不确定的实例×帧数 | 278 | 3 |
| 全路径类别冲突的实例×帧数 | 0 | 0 |
| 不能按已观测锚点唯一对应的实例×帧数 | 0 | 0 |

四个实例首次出现时间仍为0、6、81、94。新旧身份比较仅使用已观测 marker 的几何锚点，要求0.25 m范围内双向唯一，不读取类别或私有对象 ID；本次所有对应锚点距离均为0。身份对应没有被强行补齐。

原早期 cabinet 在第23—135步持续失去关联资格，几何信息不能成为后续同类设备的可用消息。v2 中它在第8步已能应用有效几何反馈，到第82步第二个 cabinet 刚满足类别资格时，就能作为其有信息的 peer。此时第二个实例自身几何累积仍为 `[0,0,0,0]`，因此是清楚的跨实例来源案例：

| 第82步，`instance_0002` | 四结构后验概率 |
|---|---|
| G，忽略类别 | `[0.25, 0.25, 0.25, 0.25]` |
| B，类别先验且不共享 | `[0.325, 0.275, 0.225, 0.175]` |
| S，同类别 peer 共享 | `[0.342023, 0.280674, 0.219326, 0.157977]` |

S的该实例 `rho=0.6134863`，B保持0.5。S/B最大后验差约0.01702；这种差异说明共享消息已能改变信念，不能等同于更准确的结构判断或更优动作。第二个实例第87步获得自身几何后，也会反过来把早期实例的可靠性降到约0.47160；共享不是只沿“增加语义权重”的方向变化。

v2剩余不确定实例×帧为：`instance_0003` 的第95、96步以及 `instance_0001` 的第103步。原拒绝规则仍然生效。

## 不利结果与尚未验证的链路

全路径实际应用反馈总数由21降为18；原返航前两者均为15，因而本轮机制是**信息到达和可共享资格的时间变化**，不是反馈数量普遍增加。第二个 cabinet 的首次自身反馈由85延至87；最后一个实例首次类别资格由96延至102。`instance_0000`和`instance_0003`在整条路径上仍未得到有效几何反馈。新旧模型均有剩余能力边界。

本轮没有计算新候选分数、动作意向或新轨迹。v2从第8步起已改变几何证据，真实新策略可能在原第82步之前就改变运动，因此第82步后的比较只能称为“条件于原付费路径”。不能把新G/B/S共同证据历史解释为它们在线必然走同一路径。

下一项合理验证是固定原公开候选集合和原剩余预算的离线重评分：检查第82步后的非零预测、共享分数、候选排序及有可执行预算时的首次动作意向差异，并明确首次意向分歧后的离策略性质。只有确认共享差异能够进入可行动评分，才适合另起冻结的新在线版本；本轮结果本身不允许直接宣称S优于B、改善J_nav，或启动旧v1的96条主矩阵。
