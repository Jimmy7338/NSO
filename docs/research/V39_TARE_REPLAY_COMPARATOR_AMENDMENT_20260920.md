# TARE V39 比较器更正与有界续行

日期：2026-09-20。在首个已冻结 TARE 主任务完成后，固定动作复核在日志比较阶段停止。原脚本、主任务和失败目录全部保持原样。此更正只处理序列化比较错误，不改变原生规划器、参数、动作预算、传感器、TSDF、场景或指标。

## 失败事实和根因

`audit_results/v39_tare_adapter_20260920/case00` 的原生主轨迹已完成38动作，符合原资格规则。独立复核执行同38动作、39帧，各完整传感包和前缀/终点地图及网格数组的比较均已通过；在首次GT读取和质量评价之前，`verify_replay_policy` 对内存字典与读回的JSON字典直接比较而失败。

RGB cue 收据的 `pixel_counts`、`valid_depth_pixel_counts` 在内存中以整数类别为键，JSON对象读回后为字符串键。原表达式 `a[k] != b[k]` 将这种表示差异视为数据差异。将双方保存为规范JSON后，39行全部物理比较字段严格相等。原失败不是传感、路线或重建不一致，也不能直接当成已经完成质量复核。

## 更正和次数

- 原冻结文件不改。新 `run_tare_routes_v39r1.py` 继承原适配器，仅将该比较替换为已有共同 `prior.digest` 的规范JSON比较。没有数值容差，也没有删除待比较字段。
- 新续行目录复制并逐SHA核验已封存case00主任务，记录为复用的同一条轨迹，零新增World，不重跑主任务。旧失败复核目录保留在原位置。
- 额外允许一次比较器修正后的case00固定轨迹复核，随后执行原矩阵剩余3条主轨迹和3次复核。合计仍为4条实际TARE主任务；复核尝试上限从4明确更正为5，其中原失败1次、新完成目标4次。失败不从成本统计中删除。
- 新协议、修正源码、原主任务和失败SHA在续行前再次冻结。修正前后的完整TARE算法与15项参数文件SHA必须一致。原始及续行两目录共同构成此批次证据。

本更正属于执行与审计基础设施修复，不能把额外复核算作独立场景、算法重试或效果改进。TARE复核仍不重执行异步ROS策略，只重新执行已记录动作的传感、融合和测量。原360°内部视场等迁移限制不变。
