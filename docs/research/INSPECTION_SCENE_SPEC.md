实现文件：[场景与 RGB 标识读取器](/root/NSO/env/virtual3d_inspection_v4.py)、[16 项场景检查](/root/NSO/tests/virtual3d/test_inspection_scenes_v4.py)。本阶段没有改其他既有场景、规划器、主评价脚本或冻结协议；另外增加了 [感知与表面积检查脚本](/root/NSO/scripts/check_inspection_semantic_cue_v4.py) 和 [机器可读证据](/root/NSO/docs/research/inspection_semantic_cue_check.json)。

## 1. 应用假设与明确范围

应用动机是沿公共通道巡检多个工作单元：实验室、设备间或工具储存区域中的设备，正面看似相同，但背面或内部有不同的可见部件。机器人需要完成公共空间和各单元的覆盖建图，同时在离开前决定哪些设备值得绕到后面补看。单线雷达看到外轮廓并不代表窄视场 RGB-D 已完成背面表面重建。

本场景检验一个有限命题：**当初见几何相同、可见设备标识与隐藏结构相关、绕行预算有限时，语义能否改善补看分配，同时不明显破坏覆盖路线。** 长距离离开后再返回增加调度的重要性，但不自动赋予语义优势。

该域可以被限定为“具有人工设备标识和类别相关内部部件的分区设施覆盖巡检”。这是对真实应用可能性的受控简化，并未采集真实设施数据。颜色编码是本实验明确规定的标识，不是某种行业标准，也不是开放词汇识别能力。

## 2. 场景几何

`InspectionConfigV4` 继承现有传感器配置，`InspectionWorldV4` 复用 CPU 射线投射、离散运动、深度／雷达契约和位姿误差模型。

| 参数 | 默认值 | 作用 |
|---|---:|---|
| 每侧工作单元数 `bays_per_side` | 2 | 两侧共 4 个单元，每单元一个设备 |
| 单元宽／深 | 4.8m / 5.2m | 允许机器人进入并绕行设备 |
| 公共通道宽 | 2.4m | 连通所有单元 |
| 相邻单元间转移段 | 4.0m | 两侧为不可进入的设备体积，公共通道贯通 |
| 首尾入口缓冲 | 2.0m | 固定起点与初始安全空间 |
| 单元门宽 | 1.6m | 中央门口，非按策略轨迹定制 |
| 墙厚／高度 | 0.2m / 2.4m | 物理遮挡 |
| 设备外包围尺寸 | 1.2m × 0.8m × 1.4m | 两种隐藏结构使用相同外轮廓 |
| 复杂设备比例 | 0.5 | 独立几何随机流选择设备位置 |

默认总尺寸是 **18.0m × 13.2m**。最小检查配置为每侧 1 单元，9.2m × 13.2m；已构造的较长配置为每侧 4 单元、转移段 8m，**47.6m × 13.2m**。这些是几何边界尺寸，不是有效可达面积，不能把较长构造检查写成已完成大尺度导航验证。

宽度和高度由配置推导，布局尺寸必须是 0.2m 的整数倍。过窄门道、非法结构参数、断开的可通行地面或不可达检查位姿会直接拒绝构造。机器人碰撞与参考可达集合使用相同保守 footprint。所有单元、正面和后面检查位置均处于起点连通分量。

## 3. 初見几何歧义与隐藏装配

`observation_condition='ambiguous'`：设备具有相同的正面遮挡表面。低复杂度设备由实心体直接提供前表面，不再额外叠一块包含于箱体的板；高复杂度设备有正面板、3–4 层水平部件与立柱。两种设备的外包围尺寸和前表面一致；从固定正面视点看到的深度在 float32 射线数值精度内相同，从后方观测则显著不同。该性质只在明确正面条件下成立，不声称所有沿通道的斜视历史都完全相同。

每台设备还有相同的 0.5m × 0.02m × 0.24m 物理铭牌，灰色与有标识外观都保留，避免用不同外观改变深度几何。铭牌只是一块表面，不能代替隐藏部件重建。

`observation_condition='open'` 去掉整块正面遮挡板，保留相同铭牌、位置和尺寸。这个普通开放结构负控制允许几何本身从正面揭示装配类型；预期细类别的额外信息减少，但不能预先保证结果。

`hidden_parts='vertical_baffles'` 把复杂类中的水平层板换为竖直隔板，保留正面板与可见设备标识。它检验盒／架形状先验失配。这个控制与直接反转标识含义不同，不应合并。

## 4. 可见信息的两种来源

### 灰色／理想标签：只支持机制上限

默认 `appearance='gray', semantic_source='ideal'` 保留统一灰色 RGB，并提供模拟器对**当前看见表面**的类别标注。正面 RGB 与深度都相同的两种设备，在真实视觉上无法由这些输入推出不同类别。因此该模式是外部理想语义通道，用于信息机制上限，不能声称 CLIP、GroundingDINO 或任何真实视觉模型已经识别了隐藏类型。

### 人工标识／RGB 读取：信息实际来自当前图像

设置 `appearance='marked', semantic_source='rgb_marker'`：设备正面铭牌使用固定材料颜色：物理标识类 2 为蓝色 RGB `(40,100,220)`，类 3 为橙红色 `(220,60,40)`。颜色只渲染在射线真正击中的可见铭牌面，遮挡或背面不可见时不产生对应颜色。

`read_inspection_markers_rgb(rgb)` 是只接受一张 H×W×3 图像的函数，按固定颜色容差读取铭牌像素，返回同尺寸标签图。它没有 world、深度、真实类别、对象列表、房间号或未来信息参数；输出仅包含实际可见的铭牌像素，其他像素为未知 0，没有真值实例扩张。

在 `rgb_marker` 模式中，最终语义帧由这个函数产生，再应用标签失效干预。测试将模拟器所有原语义命中都改成背景，读取器输出仍保持不变，证明这条输入路径并不依赖理想标签。灰色外观接相同读取器应完全没有标签，这是保留的信息缺失对照。

这证明的是**人工标识可读性与信息来源**，不证明自然光、运动模糊、遮挡污染下的识别可靠性。它不是开放词汇模块的替代验证。回校可以先在安全设备表面加明确授权的实验标识，检验真实相机颜色／标识读取；之后换成已有设备铭牌、真实纹理和开放词汇感知时，仍需独立识别评估。

## 5. 物理类、隐藏结构与标签干预必须区分

几何类型先由种子独立生成。物理设备标识类别和隐藏装配关系由 `semantic_relation` 控制：

| 关系控制 | 可见物理标识类 | 隐藏结构与评价真值 | 预期检验 |
|---|---|---|---|
| `correlated` | 与高／低复杂度对应 | 保持原几何类型 | 有效语义先验 |
| `independent` | 独立随机流给定 2／3 | 保持原几何类型 | 类别关联关闭；单个小样本可能偶然相关，应跨种子评估 |
| `reversed` | 与通常类别—装配关系相反 | 保持原几何类型 | 先验关系反转 |

有标识模式下，关系控制会改变物理铭牌颜色；它是不同的设施关联条件，**不是保持同一 RGB 的标签干预**。灰色模式则不改变 RGB。三种关系均不改变网格、占据、深度、雷达或评价用真实复杂度分组。

真正保持物理场景不变的干预由 `semantic_condition` 定义：

- `aligned`：使用当前可见理想标注或 RGB 读取结果。
- `shuffled`：交换输出标签 2／3；物理铭牌颜色不变。
- `absent`：所有输出标签为 0；物理铭牌颜色不变。

这三个干预共享网格、颜色、RGB-D、雷达、位姿、相机内参和噪声随机流。规划器只应收到传感器帧中的干预后标签。不得让无语义对照额外运行 RGB 读取器恢复标签；如果对照本身使用 RGB，则需要明确它是否有同样标识解析能力。

## 6. 评价与接口隔离

场景暴露与原世界兼容的 `mesh`、`triangle_classes`、`reachable` 等供模拟器和固定评价器使用。`inspection_truth` 只供场景检查记录和反事实选点使用，包含单元物体索引、标识类、结构类和诊断位姿。**这些字段不在 `RGBDFrame` 或 `PlanarScan` 中，不得把 world 对象直接传给规划器。**

沿用 `ReconstructionEvaluator`：按真实三角面积采样，并由与策略无关的可达位姿格点筛选可观测表面；全场景精确率／完整率／F1 不增加类别权重。检查确认参考同时包含结构背景、简单设备、复杂设备以及层架内部的真实表面；改变当前机器人位置不改变固定参考。用真实网格自身输入评价器得到 F1=1，只验证评价一致性，不是重建结果。

未来比较继续同时报告全场景 `AUC(C2D×F1)`、最终二维覆盖、P/R/F1、表面误差，以及必要的相同观测支持误差。物体区域指标如需增加，必须事前固定且向任务适配基线公开，不能取代全场景指标。

### 已修复的物理表面积重复问题

最初按盒体直接拼接的场景，在全实心小场景中曾检出 4 组重复三角面、额外面积下界 3.36m²。只把这些重复面删除仍不能解决层板／立柱、铭牌／箱体和墙段的部分共面重叠及内部面，因此现实现对**整个场景的轴对齐实体集合提取并集外表面**，作为固定评价 mesh。

具体做法是把每个盒体的真实边界坐标作为分割平面。每个最小长方体内部的实体占据状态恒定，且只在“内部有实体、外侧无实体”的边界生成一次面片。这同时消除完全重复、部分共面重叠和内部接触面；共用顶点并保留一致分割，避免独立合并矩形导致的 T 接点。不同物理类别的体积重叠直接拒绝，而不是任意决定评价标签。

这不是 0.2m 固定体素重建。用于合并算术上相同坐标的舍入尺度为 **1e-9m**；除该数值容差外，外壳与输入轴对齐实体并集一致。传感器继续投射原物理盒体集合，已在设备正／背面逐像素核对它与并集外壳首次命中一致。

解析检查包含相同盒、包含盒、相交盒、面接触盒与非凸十字形：例如两个单位立方体错开 0.5m 后的并集体积为 1.5m³、表面积为 8m²，程序与解析值一致。全实心检查场景的 1724 个三角面全部通过向内／向外测试：向内偏移在实体内，向外偏移在所有实体外；重复面为零，网格 watertight。混合设备场景也在单元测试中对每个面做相同检查。

仍保留的评价近似是有限表面积随机采样、固定可达观察格点和相机高度，并未穷举全部连续视点；人工轴对齐世界也不是真实设施参考测量。并集外表面修复只纠正当前场景的物理面积口径，不构成规划优势证明。

**修正适用范围仅为新设施世界。** 既有 V3/V4 的 72 回合仍使用各自冻结的旧组合盒网格与固定参考，本次没有重算这些实验，不能把它们描述为已经使用唯一物理外表面。旧货架背板、立柱及层板也可能形成重合或部分共面的参考权重；当时指标仍按其归档网格定义可追溯，但应在下一阶段做外表面口径敏感性复核。该复核属于事后评价分析，不能升级为独立确认或删除旧结果。

可复用函数是 `env.virtual3d_inspection_v4.py::union_surface_from_boxes(primitives)`，输入每个轴对齐实体的 `(x,y,z,sx,sy,sz,physical_surface_class)`，输出外壳 mesh、逐三角类别和构造审计。旧 `VirtualWorldV2.boxes` 只有平面范围，不能直接恢复三维实体；不过其归档构造是逐个 Open3D box 拼接，原则上可以从每组 8 顶点／12 三角形恢复包围盒。实际提取前必须核验每组恰是八角点闭合轴对齐盒、索引分组一致且类别统一，不能未经验证按固定步长切任意 mesh。类别最好从对应冻结源码重建出的 `world.triangle_classes` 读取；旧参考 NPZ 的采样点类别不能直接冒充逐三角类别。

后续建议先在独立输出目录对旧终点网格按并集真值重评 P/R/F1，并同时保留旧参考口径。若终点差异显著，再回放已存传感器帧恢复检查点后审计联合 AUC；不修改冻结规划器、原始轨迹或原结果文件。此处所述场景修复阶段未执行旧世界重评；随后已完成[64个唯一终点复核](../../eval_results/legacy_surface_posthoc_endpoint_20260910/results.md)，旧主联合AUC仍待重算。

OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 .venv-3d/bin/python -m unittest discover \
  -s tests/virtual3d -p test_inspection_scenes_v4.py -v

**16 项检查通过**：原 12 项小场景通行、反事实一致、几何歧义、开放／失配控制、RGB 来源、固定评价和长场景构造检查全部保留；另增加解析并集面积／体积、每个场景面片的外壳性质、传感器与并集首次命中一致，以及类别体积交叠拒绝。当前测试不是闭环方法比较，测试用检查位姿不能作为规划器的默认候选。

构造示例：

```python
from env.virtual3d_inspection_v4 import InspectionConfigV4, InspectionWorldV4

config = InspectionConfigV4(
    bays_per_side=2, transfer_length_m=4.0,
    appearance='marked', semantic_source='rgb_marker',
    semantic_relation='correlated', observation_condition='ambiguous',
)
world = InspectionWorldV4(config, seed=801, semantic_condition='aligned')
frame = world.sense()  # 语义来自当前 RGB 中真实可见的人工标识像素
scan = world.scan()
```

原 `eval_joint_v2.py` 工厂本次未改变，尚不能通过旧 `layout` 字符串直接启动这个新世界。下一阶段需要显式增加新工厂、将配置与场景版本归档，并在冻结前声明种子、物理关系控制、感知模式、预算与基线。上述示例种子不是已经冻结或已运行的确认集。

优先顺序：相同历史／相同候选的真实深度反事实→普通与歧义场景的匹配闭环→独立种子确认→真实标识感知和实车局部执行。只有相对强几何对照、去语义、去新增物体机制都取得净收益，且覆盖代价符合预定界限后，才能描述整体方案在该领域有优势。
