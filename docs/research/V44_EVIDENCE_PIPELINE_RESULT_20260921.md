## 保存证据如何验证

加载器先验证完整文件清单、真实字节哈希、外部 manifest 摘要、归档／当前源码、连续 RGB-D 与扫描身份、动作收费、地图与最终预测绑定。真实开发记录另核对持久启动账本、运行计数与冻结公共导航包。有限解析夹具显式标记，不能冒充真实开发运行。

主集成夹具只有一张预构造初始观测，使用真实 CPU mapper/controller、仅有 home 的小图和预算 1，因此控制器直接停止，提交与执行动作均为 0。生成时融合一次，独立新进程再融合一次；两次分别记账，不能称为两条新实验轨迹。单元测试中的其他解析融合不混入这两个主接线计数。

新进程逐步比较完整建图收据、证据和决策，最后核对占据图与完整网格。网格枚举顺序可以不同，但几何与颜色必须满足预声明容差。首次分歧立即停止，不处理后续保存帧。该过程不创建 World、不查询未来传感、没有反事实路线含义。

主集成还确认，解析夹具与 DEV_A 的真实参考不能配对评分，明确报错 `finite fixture cannot be scored as a development episode`。失败、未返航和不完整运行保留原有身份，不能变成成功端点或从批次失败清单中消失。

## 无损编码与运行入口

新增 `scripts/run_development_v44.py`，共用 V43 五槽账本、协议、传感／规划参数和输出额度，仅把完整 `steps/NNN.json` 改为有界 gzip。四份旧收据按真实规范 JSON 计为 1,327,099 B，压缩后 208,637 B；逐字节解压相同。普通步骤不能使用终止预留，原文仍受 32 MiB 单文件限制。

独立审查还发现并修复新入口的失败处理边界：再次关闭传感器抛异常时，保留原始错误和 `sensor_close_error`，继续写失败与预约终态。原 V43 文件未更改。

旧 V40–V43 五份封存清单共 **397 个条目**保持摘要一致；这些不是 397 个独立样本。最终验证开始前归档 **33 份源码**，结束后未变化；最终产物清单含 **89 项**，包含引用资产、源码副本与单帧夹具。

独立只读复核再次确认上述摘要、两张地面域的障碍排除与连通性、全部设施库存及主夹具计数。复核未重新生成参考、执行控制器或融合 TSDF。收据位于 `audit_results/v44_independent_pipeline_review_20260921/result.json`。

## 存储结论与下一步

真实入口最后预检可用 **7,931,543,552 B（约 7.39 GiB）**，要求 **10,737,418,240 B（10 GiB）**，缺口 **2,805,874,688 B（约 2.61 GiB）**。门槛在读取场景资产与预约前拒绝，因此新增 World、真实传感轨迹、启动槽位和物理重放均为 0。

审计没有找到足以填补缺口、可安全删除的项目临时数据。大量旧产物已硬链接去重；现存 Git 历史与唯一实验不能当缓存删除。环境依赖位于主机内存盘且可用，但这不能替代实验结果的持久空间。

下一步仍是空间满足后运行 R2 往返诊断，再依次运行 DEV_A/C 的 G/S 四个自主槽位，使用这里预声明的参考与摘要评价。真实运行必须经过独立重算和完整离线评分，才进入误差分析、语义收益判断及后续多场景／外部基线矩阵。若需要调整原最低空间门槛，应单独显式修订协议，不能由本次压缩结果自动视为豁免。
