## 1. 我对项目的理解

研究任务是未知室内环境中的主动覆盖探索：在动作或路径预算内探索更多可通行区域，减少无效长期目标、重复访问及多房间间的低效移动。它与指定物体目标导航不同。

项目基于 Active Neural SLAM 的分层结构：RGB-D 观测 → 地图与位姿估计 → 全局长期目标 → FMM 短期路径 → 局部动作。你在此基础上增加语义密度、结构和前沿奖励、可达性预测，以及回环和补全相关组件。

目前存在两套论文叙事：

| 材料 | 主要设计 | 与当前运行路径的关系 |
|---|---|---|
| `面向未知大场景的语义增强与结构感知主动覆盖式探索 (2).pdf` | YOLOv8、语义/结构/前沿融合奖励、普通 RPN；回环与 SSC | 更接近现有主循环；PDF 共 9 页，正文到方法部分，没有完整实验章节 |
| `Semantic_Enhanced_Active_SLAM_Paper.tex`、新版 README | OV-SDF、STGHP、RPN-UQ、IGCR 四项机制 | 新模块有实现，但重要调用链和证据尚不完整 |

论文首先应统一版本。建议以原题目的“语义增强与结构感知主动覆盖探索”为主线，把已经实现且得到实验支持的部分写实；开放词汇、UQ、回环、SSC 按完成程度列为扩展，避免必须同时证明四项新机制。

### 2.3 对 paper_fast 的复核结论

1. 两个原始矩阵均为 **80 × 20**，各有 80 条完整方括号记录，不是文本换行造成的假回合。
2. 评估日志实际配置为 `eval=1`、`num_processes=4`、`num_episodes=20`、`max_episode_length=500`，所以是 **4 × 20 = 80 个进程-回合记录**。文档中的“1 进程、多场景轮换解释 80 条记录”需要修正。控制台出现 Cantwell、Edgemere、Greigsville、Ribera 四个场景文件名；仍需逐回合清单确认分配与重复情况。
3. 原始覆盖率矩阵终点均值为 **0.79545914125**，总体标准差为 **0.25739199838**，与已有 JSON 一致；这些曲线单调，终点等于各行最大值。可以标作“历史运行观测值”，还不能当作冻结模型、20 个场景的正式主实验。
4. 日志明确出现 `train_goal_reachability=True`，并持续报告 Reach Loss。这与当前源码的评估更新路径一致，正式比较应修复后重跑。
5. 面积矩阵可复算出均值 12122.9875，但源码显示该量混入其他奖励，**暂不得标作 m²**。无法仅凭这个累计总量还原真实面积，不能简单统一除以某个常数修正。
6. 在线 Paper coverage 是另一条未正确累计的流；4.38% 不能直接解释为“语义覆盖率”。缺失或被筛掉的漂移也不等于零漂移。
7. 原报告对 20 个采样点的步数对应有误；按 25 步周期应先核对采样时机再标横轴。不能把第 2 个采样点直接写成第 100 步。
8. 汇总脚本删除零覆盖/零漂移样本，会改变统计分布；零值应保留，缺失值单独记为 `null` 和有效样本数。

保留全部原始记录；输出新的审计版结果，不覆盖历史文件，也不把历史值当作新实验。

## 3. 无 GPU 的可行边界

`--no_cuda` 只改变 PyTorch 计算设备；它不能自动解决 Habitat 的图形渲染与场景资产依赖。Habitat 的 headless 指无显示器运行，仍涉及 EGL。新版官方排障文档也提到 CPU 渲染驱动，因此不能笼统说“Habitat 永远无法在 CPU 上运行”；本项目旧版本是否能软件渲染，应单独验证，不能当作计划的默认前提。[Habitat-Sim v0.2.4 安装说明](https://github.com/facebookresearch/habitat-sim/tree/v0.2.4)、[Habitat-Lab 图形排障](https://github.com/facebookresearch/habitat-lab/blob/main/TROUBLESHOOTING.md)。新版文档不保证本仓库旧版本可用。

| 工作 | CPU 主线的安排 | 能支持的结论 |
|---|---|---|
| 日志审计、统计与论文整理 | 立即做，无需任何权重 | 历史记录的正确解释、复现性 |
| 二维栅格模拟、FMM/A*、拓扑图与目标选择 | 作为闭环实验主平台 | 明确观测/执行假设下的探索效率 |
| RPN 小网络离线训练与校准 | 小地图、小 batch、限定样本；先基准测试 | 相应数据分布下的预测性能及闭环作用 |
| CLIP/YOLO 冻结推理 | 真权重与图像到位后小样本运行、缓存 | 感知模块效果；不自动证明三维覆盖增益 |
| 历史 RGB-D/地图回放 | 有历史数据才启用；当前仓库未发现相应完整缓存 | 相同观测上的模块差异、耗时、地图一致性 |
| 完整在线 PPO 与 RGB-D Habitat | 不设为 CPU 主线前置条件 | 软件渲染/设备验证通过后另定预算 |
| GroundingDINO、深度 SSC、NetVLAD 回环大规模实验 | 延后，优先缩小贡献范围 | 没有对应实验就不作性能结论 |

软件渲染尝试设置半天至一天的排查上限：有最小场景时验证 RGB/depth 输出、连续步进与速度；不能稳定运行就继续二维主线，不反复迁移仿真器版本。

**固定轨迹回放不等于闭环探索。** 更换策略会改变未来位置和观测；不能给新策略强行播放旧轨迹帧，再把分数作为新策略覆盖率。也不能用已有轨迹直接替代 PPO 所需的新策略在线数据。

## 4. 建议的论文范围

默认保留两个可独立验证的研究问题：

- **RQ1：语义与结构信息能否在相同预算下提高未知多房间环境的覆盖效率？** 同时报告几何覆盖与语义目标发现，允许两者出现取舍。
- **RQ2：可达性筛选能否减少无效目标及重复移动？** 先做几何可达性和普通 RPN，再决定是否增加 UQ；几何连通与固定步数内具身成功需要分开定义。

贡献表述以实验为准：基础版是语义/结构引导和可达性约束的探索系统及可复现实验；RPN-UQ 或开放词汇可作为扩展贡献。若只用合成语义标注，只能支持语义规划机制，不能声称真实开放词汇视觉泛化。

保留 ANS 主干代码用于后续三维接入。CPU 平台默认用显式前沿评分选择全局目标、栅格规划执行动作；应标注为“NSO 机制的 CPU 验证实现”，不能把它命名为已经复现的完整 ANS+PPO NSO。

若导师要求论文必须包含原题目的完整三维 RGB-D 实验，则纯二维证据不充分：需要拿回有效历史实验材料，或把短期 GPU/可用图形设备验证变成最终必做项。第 1 周就与导师对齐这一要求，避免第 6 周才发现范围不被接受。

### 第 3 周：接通语义、结构和可达性机制

2026-09-10 已完成 CPU 机制接通、候选级普通点估计 RPN 离线训练、10 回合标签采集和 36 回合开发消融，详见 [实现与结果](CPU_MECHANISM_INTEGRATION.md)。42 项检查通过。当前结果支持模块实际影响决策，但不支持平均覆盖优于几何基线；第 4 周冻结正式实验前应先处理开发结论和地图内容隔离。候选 MLP 是明确独立的新架构，并非原卷积 RPN/UQ 的已训练复现。

工作：

- 对门/狭窄通道先切分再连边；给房间节点稳定标识，按可达前沿选择目标，避免选择障碍中的房间质心。
- 将语义密度与结构信息实际送入候选评分；每次决策保存各分项及最终选择。
- 先加入几何可达性过滤与失败回退，再训练小型普通 RPN；可选接入 RPN-UQ。
- RPN 标签分开：几何是否连通、既定局部控制器能否在预算内到达。未尝试的目标不能直接当失败；未知区域不能伪造具身标签。

### 第 4 周：冻结实验协议，完成主要对比

## 6. CPU 主实验协议

### 6.1 数据规模与运行预算

推荐起步设置：分辨率 0.1 m/格，128×128 或 256×256 地图；机器人和门宽以米定义，再换算格点。二维地图的物理尺度、房间数和传感器覆盖比例都需要报告，不能仅凭地图名称声称“大场景”。

调试用 10 张地图；正式测试建议 **5 类布局 × 每类 10 张地图 × 每张 3 个起点 = 150 回合/方法**，每回合 500 个原子动作。建议 6 个主要配置，总计 900 回合、450,000 个动作上限；UQ 与敏感性作为额外实验。

这不是耗时承诺。由第 2/4 周实测估计总运行时间：`回合数 × 每回合平均秒数`，再留出重跑余量。资源不足时先缩小重复数量、地图规模或感知频率，并在正式测试前固定变更；不能看到测试结果后挑地图。

RPN 起步用 64×64 局部图、batch 4、有限磁盘样本和少量训练 epoch；预算允许再增大。使用较小网络会形成新配置，不能直接假定与原权重兼容。避免沿用 2,000 张大浮点地图常驻内存的默认缓冲设置。

### 6.2 方法与消融

| 配置 | 用途 |
|---|---|
| B0：最近可达前沿 | 最小几何基线 |
| B1：预期可见未知区域与路径代价评分 | 较强几何基线 |
| B1 + 语义 | 语义的增量作用 |
| B1 + 结构 | 拓扑/结构的增量作用 |
| B1 + 语义 + 结构 | 两者协同 |
| B1 + 语义 + 结构 + RPN | 普通可达性预测增量作用 |
| 上一配置换为 UQ（可选） | 不确定性的额外收益 |

从完整 CPU 配置移除语义、结构或可达性，补齐能隔离单一因素的对照；优先复用已相同的配置结果。所有方法使用同一传感器、局部执行器和碰撞规则。

这里的几何约束先基于已知地图。神经 RPN 若预测未知区域或预算内成功，必须在协议中标清任务；不应让几何真值基线获得策略看不到的信息。

IGCR 分为两个验证层次：可以在 CPU 上验证熵计算、先验/后验以及目标评分效果；若把它改成候选评分函数，应明确属于规划增益实验。只有实际训练并比较奖励不同的策略，才能论证“IGCR 奖励提高 PPO 学习效果”。冻结同一 checkpoint 后只改奖励日志不会改变策略，也不是奖励消融。

不将简单的“开关语义”配置直接标成 SemExp、PONI 或 OVRL。没有按原方法实现和对齐任务的基线，放在相关工作中讨论，不能填进自测排名表。

### 6.3 指标、统计与有效性

- 主指标：`覆盖率 = 已观测且属于起点可达自由空间的格点数 / 起点可达自由空间总格点数`。真值只用于评价。物理面积为分子乘分辨率平方。
- 预算：报告固定动作数覆盖率和覆盖-路径长度曲线；转向消耗动作但可能不增加路径长度，二者不可混用。
- 效率：归一化覆盖曲线 AUC、达到 80%/90% 覆盖的动作数；未达到时记未完成比例及截尾，不能删除困难回合。
- 行为：无效目标数/目标尝试数、在固定局部预算内到达目标的成功率、重复访问比例、碰撞率；重复栅格计数应区分原地转向。
- 感知：若使用人工/合成语义，明确为可控语义输入；真实视觉实验另报投影误差与检测/查询效果。
- 可达性：按地图分割的测试样本报告 PR-AUC、Brier、ECE 和校准图，连通性标签与具身标签分列。
- 漂移：二维无位姿估计时标“不适用”；有估计轨迹才报告对齐后的平移 ATE，角度误差单独报告。不能由已知位姿模拟器的零误差宣称 SLAM 改进。
- 统计单位以地图为主：先平均一张地图的多个起点，再计算跨地图均值/标准差和配对差值置信区间。可用按地图重采样的 bootstrap；不要把大量相邻步骤当独立样本。
- 零值保留、缺失值标空、失败运行披露，报告有效地图/回合数量。参数只在验证集调整；不以 p<0.05 或某个覆盖率阈值作为实验成功条件。

## 8. 可选三维验证分支

如果后期能短期使用 GPU/可用图形环境，先恢复必要的 SLAM、Local、Global 真权重和少量授权场景，确认版本与输入通道。旧普通 RPN checkpoint 不能无验证地当作 UQ checkpoint。

先做两场景短回合验证：渲染正常、地图合理、权重冻结、指标独立、模块真的参与决策。之后可做 3–5 个场景、每场景 5 个固定起点、500 步、ANS 与有限改进配置的配对验证；这是有限三维补充，不能写成原计划的 20 场景 × 50 回合大规模复现。

设备时间优先用于验证和导出后续 CPU 可分析的数据，其次才是必要的短时微调。新语义输入改变通道数或分布时，要验证策略兼容性；随机初始化的新模块不能直接被称作训练完成的 NSO。

任何 GPU 时长/费用都在短跑测得 FPS 后估算，本计划不预订、不购买、不启动付费资源。
