# Probe 08, alignment and restoration

The B experiment temporarily used zero keyframe thresholds for one standard-navigation probe, not an NSO action. It reported an arrival and 0.224942 m CAN distance. On the same 150 scan timestamps, the original and B estimators both had no jump violation during this run; this does not show that B was necessary or more accurate. Relative to the initial fixed alignment, B and the original estimator differed by 82.815 mm and 1.359° after 416.359 s. The start/end measurements are not continuously observed independent ground truth, but they do not support promoting B as the long-term default.

The original default keyframe matcher was restored. The CAN velocity adaptation remains; a fixed same-stamp SE(2) alignment maintains coordinate continuity for the existing map and TSDF. It is not an accuracy correction. The zero-keyframe shadow was retired. At the archived final check the active bridge PID was 1084227, map/reconstruction processes remained present, and the user-facing control status was inactive. These are timestamped observations, not ongoing guarantees.

The report retains terminal `native_driver_fault:8` 15.463 ms after goal completion. It is recorded as the external guard/stop cleanup sequence, not a demonstrated chassis fault. CAN zero feedback was confirmed; consult the original report for independent-observation limits. Earlier probes 05 and 06 failed; their full negative records remain in the prior package. Original probe08 telemetry, sensor/CAN rings, parallel-source analysis, the staging candidate, both alignments, deployment/restoration receipts and tests are preserved. The probe began from a different actual start from other cases and does not measure NSO benefits or matched comparative efficacy.

`probes/zero_keyframe_offset_08/analyze.py` is the relocated read-only copy: it loads package-relative records and prints complete analysis JSON rather than overwriting archived results. With ROS Noetic Python message definitions and NumPy, run `/usr/bin/python3 -B probes/zero_keyframe_offset_08/analyze.py`. On the original system it regenerated the archived `parallel_estimator_analysis.json` exactly. `analyze_source.py` preserves the original file whose SHA is recorded by the independent analysis manifest; paths and writes in that original are machine-specific and it should not be run as a portable analysis. Some original JSON retains local absolute paths as provenance.
