# Probe 07 and retained CSM reference diagnostic

This is a supplemental evidence snapshot; existing probes 05 and 06 remain unchanged and failed to arrive after odometry-jump stops. Probe 07 was a separate standard-navigation diagnostic from a different actual starting pose, not an NSO action or a matched comparison. It reported one arrival, 14.165 s and 0.194964 m CAN distance. Recorded terminal error was 0.034105 m against the DWA 0.08 m tolerance; the independent supervisor acceptance field was 0.15 m. Neither CSM-based arrival nor one success independently establishes localization accuracy or repairs intermittent matcher jumps. `native_driver_fault:8` occurred after arrival during the explicitly recorded external-guard stop/cleanup; it is not a chassis error code. CAN stop feedback was confirmed; no independent physical stop observation was recorded.

Probe 07 preserves its raw 800-frame rolling CAN ring, 150-scan/150-pose ring, telemetry, configuration, goal, restoration, mission/result and event records, plus bounded analysis. The earlier 238 of 1,038 admitted CAN frames are absent; all 149 retained scan intervals were checked for recorded endpoint coverage and timestamp freshness. Original kernel timestamps and decoded CAN samples are used; zero-order hold between samples models intersample movement and does not establish continuous ground truth. The two scripts `probes/control_can_offset_07/analyze.py` and `can_source_audit07/extract.py` write JSON to stdout, use local package inputs, and require ROS Python message types and NumPy. Their outputs reproduced archived results on the source machine; `CAN_capture_audit` path was relocated in the package copy.

`instrumented_csm_candidate/` reconstructs the recorded 06 state candidates from the existing published probe06 scan ring and uses the installed matcher library; reference096 reproduces the 50.105966 mm live jump. `correspondence_audit/` identifies residual concentration without identifying a physical object or declaring a fix. Scripts use isolated ROS master ports and separate generated outputs; see each README. The saved `state_fixture_receipt.json` documents hashes of the original local scripts/binary and original port, not the relocated publication-copy scripts; source contents and paths are described separately and no binary is included.

`capture_scripts/` preserves the original probe and receive-only bounded CAN capture source used in this experiment. `run_short_probe.py` is a live mission tool, not an offline replay: it can start robot motion, changes DWA parameters temporarily, and retains original machine-specific paths. It must not be invoked as an analysis command; it is included for provenance only. No candidate parameter change or inferred policy improvement is deployed by this evidence package. Results of additional ongoing candidate investigations are not included.
