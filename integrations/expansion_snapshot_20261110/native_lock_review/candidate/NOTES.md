Offline candidate only. Not deployed or approved for robot use.

Change: replace shared timed mutex with preallocated SPSC triple buffer. Atomic middle slot owns neither producer nor consumer data; each exchange relinquishes one slot and acquires another. Producer cannot overwrite front until consumer relinquishes it. acq_rel exchange provides the required visibility/reuse ordering. All payload fields remain non-atomic because slot ownership excludes overlapping access. Atomic flags reject overlapping producer or consumer entry rather than waiting. Runtime construction rejects target atomics that are not lock-free. The existing ROS spinOnce driver is copied unchanged; its single callback thread is the intended producer, PeriodicSender the consumer. Non-overlap is enforced; thread identity is not pinned, so a quiescent thread handover is permitted.

Numeric constants and SourceContract unchanged: 20 ms period; >40 ms sender gap; >=100 ms accepted-input TTL; >80 ms wall source age; .10 m/s and .30 rad/s bounds. Producer validates each input including superseded zero and TTL gaps, then publishes only a completed snapshot. Consumer timestamps after ownership transfer to avoid a freshly published timestamp appearing to be in its future. Source validation stays before gate submission in the unchanged driver.

Changed fault semantics, explicitly:
- Ordinary producer preemption does not fault6; consumer uses the prior completed publication and its original TTL. A producer paused before first publication leaves the consumer unarmed and sending zero, without input expiry until publication.
- fault6 remains a permanent zero latch on actual overlapping producer or overlapping consumer ownership, both programming-contract violations. Normal cross-thread writer/reader overlap is intended and never faults6.
- Clock regression now checked separately for producer and consumer, with an additional consumer snapshot timestamp check. The old shared total order is gone.
- TimingRow.lock_acquired_ns now records consumer ownership-claim completion, NOT timed-mutex acquisition; schema otherwise retained. Interpret candidate traces accordingly.
- Publication and sample no longer serialize stop/expiry across one mutex. Fault is still checked before publish, after sampling, and before SDK send. A fault arriving after any check may race with the next operation, and already entered SDK calls cannot be retracted. No claim of equivalence across all stopping interleavings.

Validation: run_validation.sh compiles actual candidate header with C++11, runs adapted existing attended/timing tests, then bounded concurrency test and original-header delayed-holder reproducer. Tests cover coherent v/w under 200000 publications, private-seam pause before publication, old command retention through 80ms then original 100ms expiry, rejected late publication after expiry, firstzero even when superseded, invalid/speed/source contract, external/shutdown latch, ownership fault6, exact40ms/+1ns and expiry boundaries, monotonic clock, timing ring and transport exception behavior. The source-age callback behavior is modeled with the actual unchanged SourceContract/gate methods; ROS itself is not run. Stress timestamps advance by 1ns per publication; the consumer checks the timestamp parity against v/w and samples at that snapshot time to isolate payload/freshness-field coherence from host scheduler deadlines. This is not a scheduling qualification. TSAN could not link: system lacks libtsan_preinit.o; no TSAN pass claimed. No firmware/physical stopping evidence provided.
