# Live trajectory and semantic-map display

This update adds a read-only dashboard at http://127.0.0.1:8766. Its camera, occupancy map and 3D cloud come from the existing8765 display; the original reconstruction process and in-memory TSDF were retained. No robot motion was issued to test this UI. The existing live controller diagnostics are a separate task.

At inspection, the old pose stream was fresh (about0.1s old), but the robot had stopped after a CSM fault. Its short trajectory occupied only a few pixels at full-map scale. The old display also sampled trajectory only when `/api/state` was requested. The overlay now samples TF independently at5Hz, keeps at most5000 odom-space points, and transforms the complete trace with the current map correction. Its initial45-point trace was accepted only after matching fresh source pose/time/frame evidence. This is display-source validation, not an additional planning gate.

The UI provides follow, fit-trajectory and full-map views, contrasted trace/start/end markers, a scale bar and separate localization/control status. Follow mode expands for current semantic observations. A semantic layer toggle controls actual class labels, model scores and sampled visible-surface XY hulls. Such hulls are not complete object outlines or evidence about hidden geometry. Old source timestamps are retained and stale observations are not presented as new.

A single CPU worker reads the existing atomic RGB-D display packet, calls the same pinned YOLOE frontend/prompts/configuration as the research integration, and projects measured segmentation support using the packet's intrinsics and odom_from_camera. It runs at most once per5s with one Torch/BLAS thread. Every update replaces the current detection set: no invented objects, bounding-box masks, persistent identity tracking or hidden completion is added. Floor/wall predictions are omitted from the object label layer. This observer output does not feed research policy decisions.

The first actual check detected exhibition counters and a cabinet, with low, explicitly displayed model scores. These labels are predictions, not verified categories. Camera extrinsics remain the user's deferred old calibration, so positions are explicitly approximate. No precision/coverage/semantic-benefit claim follows.

Validation:8 overlay source/transform/age tests,11 semantic geometry/schema/empty/stale tests, frontend V8 checks, and an isolated Firefox browser check against the actual8766 service. Browser checks cover visible camera/map, toolbar modes and semantic toggle. Two live API samples verify advancing pose and semantic source stamps while the original reconstruction frame count continues. The headless browser uses the existing sparse canvas fallback if WebGL is unavailable; this does not alter the reconstructed volume or normal WebGL display.

Runtime files/tests are under docs/research/onboard_20261104/deployment/hybrid/. Restarting overlays requires the existing base display and its current packet path; do not start a second reconstruction source merely to update labels. The current local process/epoch paths are recorded in PROJECT_PRIORITIES.json. No ROS command topic, navigation goal or CAN transmitter is created by either new process.
