# Sensor-frame and floor reference: read-only audit

`runtime/joint_observation.py:45` defines `freeze_joint_grid(... floor_odom_z_m=-.233)`, with no calibration derivation in that function. The tested fresh C/S configurations record that value and the preparation script explicitly says it was retained and not newly measured. The evidence reviewed does not establish where its numerical value was originally measured; it must not be presented as a calibrated floor height. The transform sets planning Z translation to `-floor_odom_z_m`, leaving the actual XY and yaw placement unchanged.

`nso_bridge/joint_engine.py:402` and `:406` multiply the actual captured odom-from-camera and odom-from-laser by that planning transform. RGB-D backprojection and TSDF use actual K, depth and this actual transformed camera pose. In `joint_vendor/nso/mapping3d.py`, finite laser rays use the actual transformed laser pose; hit/free grid placement uses XY, while depth endpoints become occupied at planning heights strictly between 0.15 and 1.2 m. The independent navigation grid is resampled through map/odom/planning XY and unioned downstream. This does not imply that a changed Z leaves the whole downstream map unchanged: it changes depth classification and 3D voxels/TSDF coordinates.

The forecast path is distinct: `joint_vendor/env/virtual3d.py:46` constructs a hypothetical camera from grid pose and `config.camera_height_m`; `nso_bridge/exploration_joint_policy.py:171` uses it for candidate prediction and `aperture_support`. The recorded nominal camera and laser heights (0.536/0.684 m) are planning constants, not measurements of current floor-relative height. The nominal laser height also occurs in virtual sensor geometry; actual scans use captured TF. Correcting nominal forecast geometry can change aperture, candidates and scores. Even a purely coordinate-ground-reference correction changes measured occupancy and may change the policy through its input; report it as a calibrated-input adaptation, not a proof of unchanged actions. Do not alter objectives, thresholds, circle, candidates or sensor point sets.

The existing three-frame audit `analyses/rapid_evidence_20261108/physical/S_anchor_failure/ground_three_frame_conclusion.json` found a visually hypothesized coherent plane about 0.093–0.101 m above the declared floor under the then-used camera transform; the alternate old-TF reprojection gives approximately 0.103–0.111 m. These values share an episode and selected ROIs, not independent truth. Independent floor/base height and mount/axis measurements, held-out positions/frames and ROI validation are still needed; camera extrinsic, floor reference, depth bias and local slope remain possible contributors.

A reviewable next implementation would add an explicit, frozen, versioned external calibration profile to the capture configuration (reference frame, epoch, units, uncertainty, acquisition method, independent measurement and content hash); fail closed when required fields or TF/epoch agreement are missing. Derive the odom floor plane/height from independent predeclared floor observations or physical measurements, never from whether an episode's failure disappears. Preserve original RGB-D/scan and fixed original classification thresholds, navigation and sensor transforms. Validate sensor-coordinate and floor-plane geometry on held-out original frames, with original and proposed projection heights, all occupied/free/unknown transitions, laser and nav-grid contributions, confidence/uncertainty, occupied provenance and action/termination differences shown side by side. Compare scan points and known vertical obstacles as well as floor points; no automatic occupancy clearing. Calibrate hypothetical sensor heights separately from actual TF only after measuring sensor-to-floor geometry, and explicitly disclose any resulting decision change. An offline 0–13 mapper replay can test consequences after the profile is fixed, but it would be a counterfactual on one episode, not physical truth, policy efficacy or an approved deployment.
