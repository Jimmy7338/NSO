# ROS viewpoint exploration v3 — isolated research candidate

Select `configuration.policy_variant="ros_viewpoint_exploration_v3"`, `planner_revision="v10_3_1"`. `total_budget` is an explicit compatibility alias for the maximum actual waypoint attempts (at most40); optional `max_viewpoint_attempts` states that limit directly. `nominal_planning_horizon=40` controls only original nominal grid-route predictions and remains fixed as actual attempts are consumed. The caller's600s physical episode deadline is authoritative. There is no original-method equivalence claim.

`next_viewpoint(remaining_time_s=None, return_requested=False)` returns `target` containing `attempt_id`, full selected macro `pose`, `target_odom_pose`, unchanged selected-route data, predicted nominal grid/outbound costs and goal role. It does not emit the first20cm/90degree primitive. ROS owns the continuous path. An explicit caller return request targets the original anchor best effort; a no-positive-option fallback also uses the anchor. No implicit last-attempt or arbitrary time-margin override replaces an available original selected viewpoint. Expired physical time or exhausted actual-attempt cap returns targetNone with recorded termination. A final return already at the anchor can close early without a fictitious attempt.

`observe_viewpoint_result(path, attempt_id=0, ros_status=None, reason="bootstrap")` acquires the actual bootstrap. After a pending target, the same RPC accepts one fresh packet at its actual terminal partial/full pose with the exact sequential attempt ID and actual ROS terminal status. Status2 timeout/cancel is retained. No assigned target pose or synthetic intermediate frame is generated; each acquired terminal packet increments the actual waypoint-attempt counter once. `outcome.waypoint_attempt_charged=True`, `primitive_arrival_credit=False`; real ROS successes are reported separately. The underlying compatibility ledger's action/paid fields represent waypoint attempts, never fabricated grid primitives.

The inherited candidate geometry, category semantics and score formulas are unchanged. Actual acquired mapper, surface-quality, direction-history and semantic updates continue. Primitive gain calibration is disabled/frozen: a multi-meter macro is not fed back as one forward20cm or90degree turn. This explicitly changes calibration behavior while preserving score formulas.

Actual failures are recorded without any candidate exclusion, blacklist, re-ranking or score penalty. The exact inherited chooser's selected object is reused, including its original score/cost/ID tie-break and option metadata. A repeated unreachable goal can therefore be selected again if acquired evidence does not change the original choice; this limitation remains visible rather than silently changing the policy.

## Deployment boundary

Only candidate `nso_bridge/joint_engine.py` (RPC dispatch/factory) and `nso_bridge/ros_viewpoint_exploration_v3.py` require research deployment. The candidate's `joint_vendor` is a local symlink to the untouched vendor reference for offline tests; do not deploy or archive it as new source. Active v2 engine bytes were restored and checked against its saved implementation hash. Coordinator/mission are owned by the other agent/root.

`tests.log` records30 focused test executions, including four macro-specific cases and original/v2 regressions. They check full macro endpoints and predicted costs, actual partial failure pose, one frame/attempt accounting, no primitive gain feedback or arrival, failure-receipt preservation without candidate exclusion, finite attempt limits and best-effort return. These are software tests, not physical execution or efficiency evidence.

Partial map/feedback exceptions poison the worker without rollback: subsequent waypoint-result observations are rejected and no further viewpoint is selected. Bootstrap failure also prevents reuse. The fifth macro test injects an exception after actual map mutation, verifies retained partial map/no rollback, and verifies both subsequent RPC paths cannot reuse it.
