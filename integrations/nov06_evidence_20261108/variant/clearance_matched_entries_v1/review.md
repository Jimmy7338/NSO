# clearance_matched_entries_v1：离线审阅材料

固定规则为 `entry=.4+max(0,R−.2)`、`deep=.8+max(0,R−.2)`。当 R≥.2 时，两个目标到导航边缘的距离减去机器人半径仍为原来的 .2/.6 m；R=.2 时严格恢复原 .4/.8 m。实机 R=.7212185868 对应 .9212185868/1.3212185868 m。这是保留原几何余量的一种具名适配，不是优化得到的参数或新科学贡献。原 .35 m 投影容差、圆形、膨胀、朝向、孔径、深浅间隔、预算、返航、候选上限及原评分均保留。

`adapter.py` 仅复制原生成函数及其 globals 字典，在私有字典内替换 `VIEW_OFFSETS_M`；原导入模块的常量、代码文件和实际轨迹回放继续用原规则。分组维度复用已有 `measured_instance_association_v1`，仅在离线单状态诊断内替换既有 patch 入口，并在继续回放原动作前恢复。没有部署、ROS 调用、新检测或变体动作执行。

固定宽墙复用了此前同一 fixture，没有改边界、点、首次相机、起点、预算或评分。R=.2 时，原/scaled 在两个生成器中完整 routes 和 audit 均逐值一致。实机半径下，原入口误差 .5067605450 m，scaled 误差 .0851849660 m，entry/deep 都被原 guards 接受。此结果仅表明该规则可移除这个反例中的投影尺度矛盾；没有运行任务收益或真实可见性评估。

full01 四个实际全局规划状态 paid0/18/33/38 的 2×2 检查则未解决问题：native/instance 分组分别与 original/scaled 入口组合，全部16格的 incremental aperture 和 S prior 仍为零，G/S/X 分数与排序相同。对每种固定分组，scaled 的候选列表、路径、成本和评分都与 original 完全一致。各状态候选数为5/5/4/2；native资产数2/3/4/2，instance资产数3/13/26/23。所有资产仍拒绝于 `no_unused_feasible_aperture_pose`，deep 均依赖缺失的 entry。在这些状态，原生成器在进入投影误差判断之前就没有满足全部既有条件的 unused paid-return aperture pose，因此只移动 desired 点无效。这里没有进一步隔离预算、朝向、孔径及共同候选占用各自的原因。

原生和 instance-original 两组都与此前冻结的 full01 probe 在候选、audit、评分、选择上完全一致。全部41次原 next_action 回放符合已保存响应；每个变体只看当时已经观测的输入，不产生或假定新轨迹与后续观测。继续回放只为到达下一真实历史检查点，不能视作该变体的任务轨迹。输入使用 full01 当时的旧 TF 与地面参考修复，未替换成正在恢复的 Nov06 安装标定。

这是一个历史 episode 的四个相关检查点，加一个合成几何反例。它不提供独立样本的性能比较、覆盖效率、实跑成功率、物理安全或重建精度证据。原 full01 supervisor 收尾缺失的问题保持原状。孔径仅是假设远面的 FOV 支持，不能证明遮挡后可见；G/S/X 在每个条件下共享同一文本提示依赖的感知分区，G 不能称为完全无语义感知的基线。

若后续获准使用此规则，它会改变资产目标及可能的 candidate set，必须明确标为 `clearance_matched_entries_v1`，与 instance grouping 的授权范围分别记录。当前结果不足以推荐把它部署为 full01 的解决方案。原生产候选规则、圆形、覆盖目标及评分均未改动；本材料未发布。
