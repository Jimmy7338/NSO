# Physical entry scale audit

This is an offline configuration counterexample and a conditional geometric proof. It is not a physical experiment, reconstruction-accuracy result, or evidence of task benefit. The original circle, source code and all production files remain unchanged. No robot, detector, renderer, score evaluation or rollout was invoked.

## Source conventions

`competition_candidates_v8_1.navigation_rear_boundary`, lines 86–97, selects nearby occupied **cell centers**, extends their maximum back-axis coordinate by half a cell, and takes the maximum with the measured point rear coordinate. For the cardinal back axes generated by `measured_assets`, this is the outward **cell edge**, not the occupied center. Unknown cells do not extend this boundary.

`grid_geometry.inflated_obstacles`, lines 11–22, tests distance to obstacle centers and to the padded blocked border. A safe center must have distance strictly greater than `R + r sqrt(2)/2`; equality is blocked. `camera_pose`, lines 41–47, puts the nominal camera XY at the same grid center as the planning base. This proof concerns that executed nominal planning convention, not the true translated camera extrinsic.

`hierarchical_options_v10` lines 24–26 and 228–275 offers entry at boundary + 0.4 back-axis and deep at +0.8, with maximum Euclidean projection error 0.35. Deep requires an available entry. Wanted heading, measured-rear backside depth >0.15, positive hypothetical aperture, unused target and complete reserved return must also hold. `exploration_joint_v1` retains these entry predicates in its separate generator. Common coverage candidate generation differs between the generators; this audit does not assert full implementation equivalence.

There is no `_pose_table` function in the current restored/physical source tree or the searched repository Python sources. The actual enumeration is `orientation_graph(safe)` followed by `camera_pose(cell, heading, ...)`. The proofcheck calls these original functions and both original generators, rather than inventing a helper or copying their entry decision logic.

## Conditional necessary-condition proof

Assume a cardinal planar occupied face. Over every lateral grid column in the entry projection disk, the occupied face has the same outward edge coordinate B and a row/column of obstacle centers at B−r/2. Assume this face determines `navigation_rear_boundary`, so its normal coordinate equals B. A candidate center p in those columns has an occupied center directly along the face normal. Let d = (p−B) dot back_axis. Native footprint safety requires

`d + r/2 > R + r sqrt(2)/2`, hence `d > R + r(sqrt(2)/2 − 1/2)`.

Native entry projection to `desired = boundary + e back_axis`, with e=0.4 and tolerance t=0.35, requires

`||p−desired|| <= t`, hence `d <= e+t = 0.75`.

Consequently a necessary condition for an entry in this locally flat, wide-face case is

`e+t > R + r(sqrt(2)/2 − 1/2)`.

For r=0.2 and R=0.7212185868375829, the strict lower bound is **0.7626399430748925 m**, which exceeds 0.75 by **0.0126399430748925 m**. The proposed 0.86264 m bound would double-count half a cell because the navigation boundary is already at the edge. The continuous threshold radius is 0.7085786437626904 m. Passing this necessary test is not sufficient for heading, aperture, reachability, budget or target uniqueness.

For an aligned full occupied row, grid centers have distance `k r` from occupied centers. The nearest safe row is

`k = floor((R + r sqrt(2)/2)/r)+1 = 5`.

It lies 1.0 m from the occupied center row and **0.9 m from its outward edge**. Therefore its normal entry error is at least 0.5 m. In the concrete fixture the asset descriptor subsampling yields lateral target x=5.0175 whereas the nearest column is x=5.1; the actual Euclidean error is **0.5067605450308854 m**, not exactly 0.5 m.

This argument does not apply universally to corners, short or perforated assets, open shelves, missing occupied support, diagonal faces, a navigation boundary pushed beyond this face by another local obstacle, or a different camera/base planning convention. Such cases must be enumerated with the actual source. It does not prove that a real object is closed, a hidden face exists, or a legal camera can see through an occluder. Native aperture is hypothetical far-plane FOV support, not occlusion-tested visibility.

## Fixed original-function check

The fixture is a 50×50 grid at 0.2 m, known free except a finite horizontal occupied wall, row 24 and columns [10,40). Ends remain open; it is the local wide closed face that matters. The same 209 synthetic quality samples on a 1.8 m-wide wall patch and same retained synthetic first camera are passed through the original `observed_patches` and `measured_assets`; neither is patched. Camera-seen is true everywhere, so this tests endpoint construction rather than unknown-coverage gain. A fixed budget of 80 and current/anchor (14,25,2) are used for both radii. This resource is intentionally generous and is not a proposed physical budget. The only input difference across the two cases is the circle radius. Synthetic known-free input is a diagnostic fixture, not an acquired map or a claim that this observation history was physically collected.

Both generators select entry at R=0.2 with projection error 0.1296389216 m and full cost 18; 10 original safe/heading/backside/aperture/return-budget poses satisfy entry projection before common-target uniqueness. At physical R, none satisfy entry projection. The nearest positive-aperture, wanted-heading and return-feasible pose is (19,25,2), full cost 14, aperture maximum 0.9407998048, projection error 0.5067605450. Both generators log `target_projection_error_exceeds_limit` for entry and `deep_requires_available_entry` for deep. Thus neither increasing this fixture's budget nor a better detector removes the particular projection incompatibility. Common coverage/rotation options can still exist; this is not global planner infeasibility.

At R=0.2, the safety lower bound is only 0.2414213562 m from the edge and the first safe grid row is 0.3 m from the edge. This explains compatibility with the original smaller circle for this fixture, without establishing any benefit or universal feasibility in simulation.

## Proposal boundary

An entry/viewpoint scale adapter would change asset target locations and potentially candidate membership, and deep-entry dependency would propagate that change. It must be a named, separately approved method variant. Correcting sensor extrinsics alone is a different input/forecast issue and does not change the above nominal generator algebra.

If tolerance 0.35 and the physical circle are retained, the continuous flat-face necessary entry offset is strictly greater than 0.4126399431 m. The actual aligned 0.2 m grid imposes a stronger necessary axial offset of at least 0.55 m; with this fixture's lateral 0.0825 m discrepancy it is at least `0.9−sqrt(0.35²−0.0825²)` ≈ 0.55986 m. These are feasibility lower bounds, not optimized or recommended parameters, and no adapter value was tried. At any proposed offset, deep separation, FOV/range, unknown safety, complete return, live budget, common-target uniqueness, camera/base geometry and reachability still require native checks. A general adapter needs an explicit physical-scale definition and validation across face/corner/open-asset cases, not a blind increase of the tolerance.

Any G/S/X comparison must use identical frozen geometry and candidates, with class only affecting the declared scorer conditional on the same perception partition. Preserve the original unknown-coverage objective/candidates, original circle and safety layer, scoring weights, budget and return contract. A failed entry is retained as an absent asset role; no unknown face is credited as observed support. This audit authorizes no change or deployment.
